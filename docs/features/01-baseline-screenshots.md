# Feature 01: Baseline Screenshots for Frozen Screens (freeze --baseline/--verify)

> [Русская версия](../ru/features/01-baseline-screenshots.md)

> **Status:** Implemented (stages 1–3 plus mandatory tests) · **Updated:** 2026-09-09
> **Essence:** The UI-freeze mechanism captures screenshots of real screens across a set of viewports; a Playwright diff then mechanically catches "the layout drifted" — a layout regression becomes a machine-checkable fact with freeze context attached, not an agent's opinion.
> **Key facts:**
> - Screenshot diffing only, not functional testing; pixel comparison against Figma renders is forbidden on principle (fonts/antialiasing noise).
> - Baselines are captured only on frozen (🔒/🔒🔒) screens; the snapshot event is the freeze event.
> - Two-layer detector: a layout snapshot (getBoundingClientRect → JSON, canonical, committed to git, blocking verdict with a px threshold, default 10px) plus a screenshot hash (local PNG + SHA-256 in a MANIFEST in git, advisory).
> - Zero new dependencies: devst generates a Playwright spec into the project's `tests/visual/` and invokes the project's own runner (its baseURL, auth, fixtures, CI).
> - Every diff report carries freeze context: screen, freeze status and date, figma-dump layout version.
> **Related:** [ADR-011: UI freeze](../decisions/adr-011-ui-freeze.md) · [ADR-013: Default deny](../decisions/adr-013-default-deny.md) · [Feature 03: devst UI desktop window](./03-devst-ui-desktop-window.md) · figma-dump

## 1. Essence and principles

1. **Catch layout, not function**: screenshot diff, not functional tests. figma-dump is the reference of intent ("how it should look"); the baseline is the guard of fact ("what was frozen"). Pixel-perfect comparison against Figma renders is forbidden (fonts, antialiasing).
2. **Frozen = captured**: baselines are taken ONLY on 🔒/🔒🔒 (frozen) screens; the snapshot event is the freeze event (a log entry, PNGs visible in PRs).
3. **Responsive = matrix**: each screen × a set of viewports (mobile/tablet/desktop); baseline and diff per matrix cell.
4. **Zero dependencies of our own**: devst does NOT ship a browser — it generates a Playwright spec into the project's `tests/visual/` and calls the project's own runner (its baseURL, auth, fixtures, CI). The canon is the registry; the spec is a derived artifact ("GENERATED BY devst").
5. **Freeze context in reports**: every diff is labeled "screen Home, 🔒🔒 hard, frozen 2026-09-08, layout dump: Home (v23)" — taken from ui-freeze.md.

## 2. Two-layer detector

The author's goal: **catch a block that moved 20–100px, not a font shifted by a couple of pixels** — this is geometry, not pixels. Hence two layers:

| Layer | What | Canon | Catches | Threshold |
|---|---|---|---|---|
| **1. Layout snapshot (primary)** | `getBoundingClientRect()` of the screen's anchor elements → JSON | **in git** (KB-sized): exact numbers, PR diff as text "top: 120 → 157" | shifts/resizes of blocks, missing elements | in pixels: default 10px shift/change, per row |
| **2. Screenshot hash (secondary)** | PNG of the real screen | **local** (`docs/baselines/images/`, gitignored) + SHA-256 in a MANIFEST (git) | "looks different": colors, images, rounding | none: any hash mismatch = "look with your eyes" |

- The layout diff is the **blocking** regression verdict (numbers in the report and the PR); the screenshot hash is advisory (the pixel diff is computed locally against the stored image and attached to the report).
- Subpixel/font noise does not exist in geometry — the threshold is an honest number in px.
- Anchor selectors live in the project's non-generated `tests/visual/anchors.ts` (by analogy with profiles.ts); on divergence the agent proposes anchors from the figma-dump layout.
- Team evolution: PNG→JPEG in git (3–5x smaller) for review visibility.

## 3. Design (commands, registry, reports)

### Registry (extension of ui-freeze.md)

- Header: `Viewports: 375x812, 768x1024, 1440x900` (default set; a row may override it).
- New row columns: `URL` (the screen's route), optional `Masks` (selectors of dynamic zones: .feed, .timestamp) and `Tolerance` (maxDiffPixels).

### Commands

- `freeze --baseline [--screen X]`:
  1. generates `tests/visual/freeze.visual.spec.ts` from the registry (only 🔒/🔒🔒 rows; test titles carry the freeze status/layout version);
  2. `playwright test visual --update-snapshots` (via the project's runner);
  3. writes canon: layout JSON + `docs/baselines/MANIFEST.json` (code commit hash, date, screens×viewports, screenshot SHA-256s, freeze statuses) + a log entry. PNGs stay local (gitignored).
- `freeze --verify [--screen X]`:
  1. spec run;
  2. console summary + markdown report `docs/baselines/REPORT-<date>.md`: screen / status / viewport / verdict / link to the diff;
  3. a hint to run `playwright show-report` — the project's HTML report with visual comparison out of the box (deep human analysis);
  4. a diff on 🔒🔒 = hard regression; on 🔒 = "are you sure?"; non-frozen screens are not checked.

### Anti-fake (layout specifics)

`animations: disabled`, waiting for `document.fonts.ready`, `deviceScaleFactor: 1`, masks for dynamic zones from the Masks column, stable data fixtures (the project's e2e already handles this), per-row tolerance.

### Glue with the freeze

- Changing a baseline (update-snapshots) without a status change is a suspicious event: only with the author's explicit confirmation (the /ui-freeze rule) — an "unfreeze by eye", with the PNG diff visible in the PR.
- SessionStart: if the code of frozen files changed after the baseline commit (git dates — cheap) → "N commits after baseline — run freeze --verify".
- pre-commit does NOT run a browser (slow); verify is a ritual on drift/schedule/CI (the spec lives in tests/ → the project's CI picks up visual tests for free).

## 4. Decision protocol

| # | Question | Decision (2026-09-09) |
|---|---|---|
| 1 | Auth/staging | **A**: a Profile column in the registry + the project's non-generated `tests/visual/profiles.ts`; agent recon on the first baseline. The URL in the registry is a path; baseURL comes from playwright.config |
| 2 | Image storage | **B+ hash-canon** (it must stay free, save disk): canon in git = layout JSON + MANIFEST with SHA-256; PNGs local (gitignored). The MANIFEST diff lands in PRs as text. Losing local PNGs = a deliberate re-capture (a confirmation event). Team evolution: JPEG in git |
| 3 | Screenshot | **full-page by default**, optional per-row Selector |
| 4 | When to verify | **A** (SessionStart drift hint) + **CI for free** (the spec in tests/visual — the project's GitHub Actions picks it up on push; pre-commit/browser — no; pre-push — deferred) |
| 5 | Threshold/canon | **two-layer** (see §2): layout JSON primary (px threshold, default 10), screenshot hash secondary; canon lives on the author's local machine, browser pinning via a lockfile |

Tests (DoD): unit+golden (visual-core, 10 cases), e2e with real Chromium and drift injection (visual-e2e: baseline → +30px caught by number/rc=1 → +3px below threshold → color-only change: layout clean, hash signals) — all green (167 total).

## 6. Pixelperfect mode — implemented (v1, 2026-09-09)

Implemented: an `Images: git` setting in the registry header (plus a one-shot `--pixelperfect` flag). In git mode: PNGs are committed (the gitignore entry for images/ is removed automatically; switching back restores it), and `--verify` performs a true pixel diff (an own PNG decoder on node:zlib, zero dependencies): mismatch percentage against a `Pixel tolerance: N%` header setting (default 1%), with an antialiasing tolerance of ±10 per channel. Threshold exceeded on 🔒🔒 → blocking regression (rc=1); on 🔒 → warning. The default is still hash-canon — heavy artifacts enter the repo only by explicit setting. CI-comparable rendering via a pinned browser image remains Phase 2.

## 7. Testing (mandatory automated tests — feature DoD)

Without these tests the feature does not count as done:

1. **Unit (pure core):** layout-snapshot canonization (rects → stable JSON: anchor sorting, rounding to 0.1px); layout diff with a px threshold (a 9px shift — clean, 11px — an event; size changes; a missing anchor); MANIFEST hashes (match/mismatch/missing image = a re-capture event); spec generator — golden-file (registry → expected spec text, incl. titles with freeze statuses).
2. **Integration (fake page):** a fake page object with rects and "screenshots" — a full baseline→verify cycle without a browser, incl. two-layer verdicts.
3. **E2E (real browser, drift injection):** devDep `@playwright/test` + a mini-site fixture (3 blocks); scenarios: (a) a clean run — 0 events; (b) a CSS shift of a block by 30px → the layout diff catches it WITH the number "~30px", verdict — 🔒🔒 regression; (c) a color-only change → layout clean, the screenshot hash signals; (d) "font noise" (subpixel/AA emulation) → neither layer fires; (e) drift on 🔒 (soft) → "are you sure?", non-blocking. Reports are asserted against exact lines.

## 8. Non-goals

- Functional tests, a cross-browser matrix (one browser — the project's CI default).
- Comparison against Figma renders (forbidden on principle).
- devst shipping its own browser/dependencies.
