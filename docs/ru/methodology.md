# Методология dev-standard

> Русский · [English](../methodology.md)
>
> Часть публичной документации devst. Английская версия — источник истины; эта
> страница — её русская редакция.

devst — инструментарий для внутренней методологии **dev-standard**. Эта страница
пересказывает её ключевые идеи — всё описанное принуждается механически: командами,
хуками и CI devst; приватный документ стандарта, чтобы следовать этому, не нужен.

## Исходная посылка

Документация живёт в репозитории, рядом с кодом, который описывает, — никаких вики
и внешних сервисов. Она пишется сразу для двух читателей: людей и ИИ-агентов. Когда
большинство диффов пишет агент, доки становятся спецификацией, которую агент читает
перед каждой задачей, и аудиторским следом, который он оставляет после. Качество
документации перестаёт быть добродетелью и становится инфраструктурой.

## Уровни чтения

| Уровень | Что | Когда |
|---|---|---|
| **L0** | `AGENTS.md` + карта доков с панелью «Сейчас» | Перед любой работой, всегда |
| **L1** | Шапки доков, последний журнал сессии, открытые задачи | Достаточно, чтобы начать задачу |
| **L2** | Полные тела доков, исходники | По запросу |

Никто — ни человек, ни агент — не гадает, что читать первым. Конвенция фиксирует
это сама.

## Шапки доков

Каждый документ открывается машино-проверяемой шапкой:

```markdown
> **Статус:** актуально · **Обновлено:** 2026-09-25
> **Суть:** что это за дока, в одном-двух предложениях.
> **Ключевые факты:** 3–5 пунктов, ради которых эту доку открывают.
> **Связанное:** ADR, фичи, точки входа в код.
```

`devst check` падает, если шапки нет или её дата разошлась с git-историей файла.
Статусы живут только в шапках, прогресс — только в чекбоксах roadmap, открытые
вопросы — только в реестре задач: у каждого вида истины — одно место.

## Карта и панель «Сейчас»

`docs/README.md` — сгенерированная карта всех документов с однострочным описанием
(регенерируется командой `devst map` — вручную её не правят). Сверху в ней
проштампована панель «Сейчас» (`devst status`): текущая фаза, последняя сессия,
открытая работа. Новый агент видит состояние проекта за пять секунд; та же панель
автоматически вставляется в сессию SessionStart-хуком.

## ADR: append-only решения

Архитектурные решения фиксируются как ADR (Контекст → Варианты → Решение →
Последствия → Отклонённый вариант — одной строкой). Реестр — append-only: смена
решения означает новый ADR, помечающий старый как superseded; файлы не
переименовываются и не перенумеровываются — дыры в нумерации нормальны и честны.
`devst new adr` создаёт заготовку с правдивым номером и датой.

## Журналы сессий с бюджетом

Каждая рабочая сессия заканчивается одной записью в журнал: что сделали, коммиты,
что осталось. Жёсткий бюджет — 200 строк, целевые — 60–80: запись журнала — это
долгоживущее резюме, а не транскрипт. `devst undocumented` находит коммиты кода,
более новые, чем последняя запись журнала, и напоминает: сделал работу — запиши
отчёт.

## Реестр задач с гейтами закрытия

Задачи и открытые вопросы живут в SQLite-реестре со связями на объекты (файлы,
доки), таймерами и TTL — не в TODO-комментариях и не в чьей-то голове. Закрытие
задачи проходит **гейт**: по каждому связанному объекту требуется вердикт, а
гейт-отчёт сверяет, что задача декларировала, с тем, что коммиты реально тронули.
Протухшие задачи всплывают на доске; принцип «фиксировать, не блокировать» действует
и здесь.

## Definition of Done

У каждого репозитория есть фиксированный чек-лист DoD: тесты зелёные (включая E2E),
запись в журнал написана, map/status/check — без ошибок, ADR — если изменилось
поведение, README и карта обновлены — если изменение существенное. Хуки напоминают;
CI (`devst env --check`) проверяет, что таблица окружения в AGENTS.md не протухла.

## Фиксировать, не блокировать

Инструментарий никогда не переписывает ваш текст и по умолчанию не блокирует
человеческий коммит: CLI линтит, скилл учит, хуки принуждают — сначала
предупреждения, строгий режим — явный opt-in. Конвенции доков меняются только через
новый ADR, никогда — мимоходной правкой.

## Тиры

| Тир | Охват |
|---|---|
| **T0** | Черновик — один README |
| **T1** | Соло, по-лёгкому — карта + решения |
| **T2** | Соло, всерьёз — полная структура: архитектура, фичи, решения, roadmap, журнал, реестр |
| **T3** | Команда / мульти-репа — T2 плюс отдельный док-хаб |

`devst init <tier>` скаффолдит выбранный тир; сомневаетесь — берите тир ниже.
