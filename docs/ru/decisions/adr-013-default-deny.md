# ADR-013: Режим default-deny реестра верстки

> Русский · [English](../../decisions/adr-013-default-deny.md)

> **Статус:** принято · **Дата:** 2026-09-08

**Суть:** строка `**Режим:** default-deny` в шапке ui-freeze.md переворачивает семантику: файла НЕТ в реестре → 🔒🔒 жёстко (обычный режим — наоборот: нет записи → можно править).

**Отвергнуто:** спец-механика вроде «`!` = глобальная разрешилка» и прочие исключения поверх реестра (первый драфт) — отвергнуто автором: «реестр и так общий; разрешение выражается строкой». Семантическая простота важнее синтаксического сахара.

**Связанное:** [ADR-011](adr-011-ui-freeze.md) · dev-standard v1.3

## Контекст

Запрос автора: «инверс-режим для максимальной строгости — нет явного разрешения на редактирование → считать всё жёстким запретом». Название: default-deny.

## Решение

1. Маркер режима — строка шапки `**Режим:** default-deny` (алиас «инверс»).
2. Семантическое изменение ровно одно: **нет записи = hard** (`byDefault` в вердикте); разрешение — обычная строка реестра (свободно/мягко/спросить/не сделано, блок-правило). `!` по-прежнему вычитается из глобов своей строки, ровно как в обычном режиме.
3. Дока-слой (`docs/`, `README.md`, `AGENTS.md`) по умолчанию не запрещён — это рабочее пространство агента (иначе нельзя вести логи и карту).
4. Механика сквозная: `freeze --file/--staged` (вердикт несёт `byDefault`), SessionStart («default-deny: …»), PostToolUse («файла НЕТ в реестре — правка запрещена»), strict pre-commit блокирует. Линт: предупреждение `инверс-без-разрешений`, если в реестре нет ни одной разрешилки.

## Последствия

E2E подтверждён: файл вне реестра → «ИНВЕРС/default-deny» во всех слоях; strict блокирует коммит; разрешилки и дока-слой проходят чисто. Тесты: 6 кейсов режима (парсинг, дефолт-запрет, exemption, разрешилки, `!`-семантика, обычный режим).
