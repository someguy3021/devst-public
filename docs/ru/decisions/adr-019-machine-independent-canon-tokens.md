# ADR-019: Машинная независимость канона — токены и подстановка при install

> Русский · [English](../../decisions/adr-019-machine-independent-canon-tokens.md)

> **Статус:** принято · **Дата:** 2026-09-12

**Суть:** канон (скилл, slash-команды) не несёт машинных путей — вместо них токены
`{devst_cli}` / `{devst_repo}` / `{standard_doc}`; `integrations install` подставляет
значения машины при раскладке (расширение `patchCli` хуков), `doctor` сверяет хэши
с той же подстановкой.

**Отвергнуто:** канон-читает-метку `devst.json` (лишний шаг у агента); PATH-шим
`devst` и env через setx (системные правки; env — opt-in на будущее).

**Связанное:** [ADR-012](adr-012-integrations-install-doctor.md) ·
[ADR-018](adr-018-sea-binary-distribution.md) · T-14 · roadmap 2.2

## Контекст

Триггер — вопрос автора (T-14, дословно): «у тебя буквально в
integrations/zcode/commands написаны пути МОЕЙ машины, как на другой машине-то
запускать навыки и тд, если они будут неверные? Или даже просто в другую папку
ничего не положить!». После ADR-018 exe-first-канон получил абсолютные пути машины
автора (exe, репа devst, путь dev-standard): на другой машине установленный
скилл/команды молча указывали в никуде; канон без install вообще не должен выглядеть
рабочим. Хуки проблему уже решали (`patchCli` → `patchHookDefault` при install) —
механизм перепрошивки существовал, но не покрывал текстовые доки.

## Опции

### A. Токены + подстановка при install (выбрано)

- Плюсы: симметрично хукам; doctor сверяет с подстановкой (без ложного дрейфа);
  незаполненный токен в не-install-ленном каноне — громкий маркер «запусти install»;
  exe из ADR-018 вшивает канон с токенами и подставляет свой путь при install из себя.
- Минусы: установленный текст различается между машинами (как и у хуков — уже норма);
  канон нельзя читать «как есть» до install.

### B. Канон ссылается на метку {zcode}/devst.json

- Плюсы: ноль правок тулзы; путь всегда актуален.
- Минусы: каждая команда у агента начинается с «прочитай json»; агент должен знать,
  где {zcode}; пропуск шага = вызов неверного пути.

### C/D. PATH-шим `devst` / env `DEVST_CLI` (setx)

- Плюсы: канон максимально короткий (`devst <команда>`); env хуки читают уже сейчас.
- Минусы: правка пользовательского окружения (setx) и перезапуск шеллов — системные
  последствия против духа ADR-012; отложено как opt-in.

## Решение

**Вариант A.** `FileRule.substitute: true` (скилл + 5 команд в таргете zcode);
`prepareCanon(rule, body, canonVars, cliPath)` — единая точка перепрошивки (подстановка
токенов + patchCli для хуков), используется в install и в `diffInstalled` (canonVars
пятым параметром). Значения: `devst_cli` = cliAbs (SEA — сам exe, репа — dist/cli.js),
`devst_repo` = корень репы (SEA — каталог exe), `standard_doc` = README внутренней
методологии dev-standard, если лежит рядом с репой, иначе честный текст-фолбэк.
Неизвестный токен `expand` оставляет как есть — «незаполненный» виден глазом.

## Обоснование

- Требование автора закрывается целиком: канон машинно-нейтрален, другая машина
  = «склонировал репу / получил exe → install → doctor», переезд перепрошивается
  повторным install — отдельный сценарий переезда не нужен.
- Ровно один механизм правды о путях: install в момент раскладки, doctor при сверке.

## Последствия

**Позитивные:**
- Канон можно править в репе без оглядки на машины; install остаётся единственной
  операцией адаптации.
- Симметрия с ADR-018: exe вшивает токенизированный канон, подстановка — при install
  из него же.

**Негативные / риски:**
- Новые тексты канона обязаны использовать токены, а не абсолютные пути (ловится
  ревью/тестом-гардом — при необходимости добавить линт «абсолютный путь в каноне»).
- Установленные копии машинно-специфичны — doctor обязателен после смены CLI-пути
  (уже стандартный ритуал).
