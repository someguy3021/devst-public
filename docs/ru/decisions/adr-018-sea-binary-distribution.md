# ADR-018: Дистрибуция CLI: SEA-бинарь с каноном в ассетах

> Русский · [English](../../decisions/adr-018-sea-binary-distribution.md)

> **Статус:** принято · **Дата:** 2026-09-12

**Суть:** CLI = Node SEA-бинарь (`pnpm build:sea` → `dist/sea/devst.exe`): esbuild-бандл `src/` вшивается в копию node.exe, канон install'а (скилл/команды/хуки/таргеты/шаблоны) — ассетами SEA. `devst.exe integrations install` вшивает в хуки путь **к exe** — правки `src/` в работе больше не задевают живой воркфлоу.

**Отвергнуто:** deno/bun compile — отложены (чужой рантайм против 300 тестов; bun требует адаптер `bun:sqlite`); npm-пакет — фолбэк; Electron — запасной план [ADR-015](adr-015-tauri-ui-stack.md).

**Связанное:** [ADR-012](adr-012-integrations-install-doctor.md) · [ADR-015](adr-015-tauri-ui-stack.md) · roadmap 2.2/2.3 · разведка standalone-CLI (2026-09-12) · T-11 реестра

## Контекст

Хуки (SessionStart/PostToolUse) и zcode зовут CLI по абсолютному пути
`…/devst/dist/cli.js` (временно по [ADR-012](adr-012-integrations-install-doctor.md)).
Каждая правка `src/` без пересборки означает: рабочий воркфлоу автора гоняет
протухший dist, а сломанный dist ломает хуки. Решение автора (2026-09-12,
дословно): «сделаем Node SEA, чтобы наши правки в работе не убивали мой текущий
воркфлоу» — из развилки разведки выбран SEA: тот же рантайм, что в тестах,
`node:sqlite` нативно, ноль правок ядра.

Ограничения SEA: вход только CJS (наш dist — ESM → esbuild-бандл); кросс-компиляции
нет (первая цель — Windows, машина автора); статус Node «Active development»
(пересборка на каждом апдейте Node — осознанно, `pnpm build:sea`).

## Опции

### A. SEA-бинарь (выбрано)

- Плюсы: тот же Node, что в тестах (семантика запина 300 тестами); `node:sqlite`
  builtin; канон вшивается ассетами — exe самодостаточен; `--build-sea` в Node 25.5+
  упростит сборку в будущем.
- Минусы: нет кросс-сборки; экспериментальный статус; exe ~80–100 МБ; dev-команды
  (`bugs emit`) остаются репа-режимными.

### B. deno compile / bun compile

- Плюсы: кросс-компиляция из Windows во все цели; у bun — `--bytecode`.
- Минусы: чужой рантайм = командная матрица поверх тестов; у bun нет `node:sqlite`
  (адаптер `bun:sqlite` — вторая sqlite-реализация, против духа ADR-017).

### C. npm-пакет / копия dist/

- Плюсы: ноль сборочных нововведений; агенты всегда с Node.
- Минусы: не решает «стабильный артефакт поверх правок src» без дисциплины релизов;
  протухший dist — та же боль.

## Решение

**Вариант A.** Конвейер `pnpm build:sea` (`scripts/build-sea.mjs`): esbuild-бандл
`src/cli.ts` → `dist/sea/cli.cjs` (CJS; externals: esbuild, javascript-obfuscator,
html2canvas — devDeps, в бинаре недоступны) → sea-config с **ассетами канона**
(`skill/`, `integrations/`, `templates/`) → blob → копия node.exe → postject.

Интеграционный слой учит SEA-режим:

1. `src/sea.ts` — `isSeaRun()` / `seaAssetText()`; чтение канона: SEA — ассеты,
   репа — файлы (единая точка в `integrate-run.ts`).
2. `integrations install`/`doctor` из exe: `cliAbs = process.execPath`, канон — из
   ассетов; хуки получают путь exe.
3. Хуки (канон) получают диспетчер `devst_run`: `*.exe` — прямой запуск, иначе
   `node` — хук живёт с обеими формами CLI; `hook install` (pre-commit) выбирает
   форму в момент установки.
4. `bugs emit` в бинаре — внятная ошибка «запусти из репы» (нужны исходники и devDeps).

## Обоснование

- Требование автора — «воркфлоу не убивается правками в работе» — закрывается
  фактом стабильного артефакта: хуки смотрят на exe, пересборка dist больше не
  влияет на живые сессии.
- SEA — единственная опция без второй реализации sqlite и без чужого рантайма;
  цена (нет кросс-сборки) для текущего «Windows + агенты на этой машине» — ноль.
- Канон в ассетах делает exe настоящим установщиком (вопрос автора) — без него
  install из exe требовал бы рядом репу.

## Последствия

**Позитивные:**
- ADR-012 «запуск из репы — временно» исполнен для основного сценария; `doctor`
  смоукнет хуки уже против exe.
- Сайдкар Tauri-UI (roadmap 2.3, SidecarKernel ADR-015) получает готовый артефакт.

**Негативные / риски:**
- Апдейт Node = пересборка бинаря; подписи нет — SmartScreen предупреждает (как у
  Tauri-exe); канон в exe застывает до пересборки (`integrations install` из репы
  остаётся каноном для разработки самой devst).
- Кросс-платформа (macOS/Linux) — отдельно (CI-матрица), в этот ADR не входит.
