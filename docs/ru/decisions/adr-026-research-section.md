# ADR-026: research — полноправная секция: map и check знают каталог разведок

> Русский · [English](../../decisions/adr-026-research-section.md)

> **Статус:** принято · **Дата:** 2026-10-07

**Суть:** каталог `docs/research/` добавлен в `SECTIONS` (src/util.ts) — `devst map`
подбирает разведки-сироты в карту, `devst check` линтит их шапки/имена/карту наравне
с остальными доками, досье (`devst file`) сканирует их.

**Отвергнуто:** отдельный `kind: 'research'` — не даёт поведения сверх `doc` (везде
сравнение только с `log`), лишняя сущность в типе.

**Связанное:** T-32 · сессия 33

## Контекст

- `research/` — часть шаблона T2 с самого начала (в карте секция есть), но каталога
  не было в `SECTIONS` (src/util.ts): `devst map` не сканировал его, разведки-сироты
  не попадали в карту автоматически, `check` их не видел, `devst file` не сканировал.
- Вскрылось в сессии 33: ресерч-доку агентного кодинга пришлось добавлять в карту
  вручную; заводили T-32 (работа).
- Все шесть существующих разведок уже имеют шапки (Статус/Обновлено/Суть/Связанное)
  и упомянуты в карте — расширение юрисдикции линта ничего не ломает на существующем
  материале.

## Опции

### A. Оставить как есть — research в карту руками

- Плюсы: ноль кода.
- Минусы: единственная секция docs/ вне автоматики; линт-сироты и битые имена не
  ловятся; каждый новый ресерч — ручная правка карты (забывается).

### B. Отдельный `kind: 'research'`

- Плюсы: семантическая явность, можно later ввести разведочные спец-правила.
- Минусы: сегодня ноль поведенческих отличий — все сравнения в коде это
  `=== 'log'` / `!== 'log'`; новая ветка в типе без единого потребителя.

## Решение

**Вариант — research в `SECTIONS` c `kind: 'doc'`** и паттерном имени
`YYYY-MM-DD-слаг.md` (`^\d{4}-\d{2}-\d{2}-[\wа-яё-]+\.md$`), между roadmap и log.
Поведение наследуется общим: map (сироты → карта), check (шапка, имя-файла,
карта-сирота, счётчик в сводке), досье. `devst new` разведки не скаффолдит —
разведки пишутся вручную по образцу существующих (если понадобится — отдельная
задача).

## Обоснование

- Один объект в массиве вместо новой ветки логики — минимальный дифф, весь механизм
  (map/check/досье) уже универсален: секция ищется по `dir`, не по белому списку.
- Линт-правила на разведки не новые, а те же, что у всех доков (шапка/имя/карта) —
  это выравнивание, а не ужесточение.

## Последствия

**Позитивные:**

- Новая разведка автоматически попадает в карту (`devst map`), пропавший из карты
  файл ловится как `карта-сирота`, битое имя — `имя-файла`.
- Счётчик разведок виден в сводке `devst check`.

**Негативные / риски:**

- Разведки с нестандартным именем (не дата-слаг) теперь дают предупреждение —
  переименование старых файлов не требуется: все шесть проходят паттерн.
- Разведки без шапки, созданные «на черновик», будут шуметь линтом — по конвенции
  черновик и не должен жить в docs/research.
