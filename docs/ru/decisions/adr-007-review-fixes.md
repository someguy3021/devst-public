# ADR-007: Три фикса по итогам ревизии слабостей

> Русский · [English](../../decisions/adr-007-review-fixes.md)

> **Статус:** принято · **Дата:** 2026-09-08

**Суть:** дрейф свежести оценивается по дате коммита (не по mtime); stripFences для
код-блоков; правило «устаревшая панель "Сейчас"».

**Отвергнуто:** сверка свежести по mtime (см. ниже — ложные срабатывания на свежем клоне).

**Связанное:** [ADR-006](adr-006-env-multistack-checked-stamp.md) · [ADR-008](adr-008-standard-version-tracking.md)

## Контекст

Ревизия слабостей, прошедшая после вопросов автора, выявила три дефекта.

## Решение

1. **Ложные срабатывания mtime:** после `git clone` каждый файл выглядит
   «созданным сегодня», из-за чего правило `env-freshness` врало. Теперь свежесть
   оценивается по последнему коммиту, трогавшему манифест (`git log -1 --format=%as`);
   mtime остаётся фолбэком вне git.
2. **Код-блоки:** строки «## » и ссылки внутри ```-примеров ломали границы шапок
   доков и давали ложные отчёты о «битых ссылках». `stripFences` — доковые регекспы
   работают по тексту с вырезанным содержимым fence-блоков.
3. **Устаревшая панель «Сейчас»:** строка «Последняя сессия» в панели «Сейчас»
   обязана всегда равняться максимальной записи в log/ (`devst status` это чинит).

## Последствия

Regex-парсер остаётся (mdast отклонён: см. обсуждение — обратная запись, GFM-таблицы,
производительность; держится в долгом TODO с триггером «при первых реальных ложных
срабатываниях»).
