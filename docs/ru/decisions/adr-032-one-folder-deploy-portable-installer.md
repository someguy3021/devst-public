# ADR-032: деплой одной папкой, portable-установщик, стандарт в монорепе

> Русский · [English](../../decisions/adr-032-one-folder-deploy-portable-installer.md)

> **Статус:** Принято · **Дата:** 2026-10-26
> **Суть:** продукт — пара экзешников, деплоящихся рядом (`devst.exe` + `devst-ui.exe`);
> деплой — ручное копирование пары в стабильную папку инструментов конкретной машины,
> без скриптов и личных путей в репе. Установщик вшивает путь запущенного им exe
> (portable-first: чекаут исходников не нужен), а легаси-плейсхолдеры «путь к репе» /
> «путь к внешнему стандарту» удалены — стандарт документации теперь живёт в монорепе devst.
> **Связанное:** [ADR-018](../decisions/adr-018-sea-binary-distribution.md) (SEA-бинарь) ·
> [ADR-019](../decisions/adr-019-machine-independent-canon-tokens.md) (токены канона; частично заменён)

## Контекст

«Сборка» и «деплой» были одним файлом: хуки, скилл и MCP-конфиг указывали на свежий
бинарь внутри дерева исходников. Пересборка — или даже проверка сборки — перезаписывала
бинарь, который исполнял живой пайплайн (SEA-сборка ещё и спала в ретраях, пока файл
держал работающий MCP-сервер). Автор держит задеплоенные инструменты всех проектов в
стабильной папке инструментов конкретной машины: папка на тулзу, экзешники рядом.

Вторая, более старая трещина: установщик вшивал в установленный скилл ссылки на чекаут
исходников — фолбэк «для разработки запусти CLI из репы» и путь к соседнему репозиторию
стандарта документации. У пользователей нет ни того, ни другого — свежая установка могла
вшить битые ссылки (известный класс дефектов), а переносной exe вне чекаута деградировал
до «стандарт не найден».

Разведка показала безопасную землю: команда `check` внешний стандарт не читает —
ожидаемая версия вшита в CLI и сверяется с меткой проверяемой репы; внешний репозиторий
нужен был только ради вшивания пути к его README в текст скилла.

## Решение

1. **Сборка ≠ деплой.** Продукт — пара `devst.exe` + `devst-ui.exe`, собираемая рядом
   одной командой. Деплой — ручное копирование пары в стабильную папку инструментов,
   которую машина выбирает сама. Никаких деплой-скриптов и личных путей по умолчанию в
   репе — сборка физически не может задеть работающий деплой.
2. **Установщик переносной.** Установщик вшивает путь того exe, из которого запущен:
   куда пользователь положил свой exe, туда смотрят установленные скилл, команды, хуки и
   MCP-конфиг. Легаси-плейсхолдеры и дев-строки удалены из канона; дефолтный путь CLI
   внутри хуков теперь пуст, пока установка его не прошьёт, — незашиштый хук молчит
   вместо ссылок на несуществующие пути. Ключ MCP-сервера, в отличие от пользовательских
   записей, при каждой переустановке перепрошивается на текущий бинарь.
3. **Стандарт живёт в монорепе.** Стандарт документации переехал в `docs/standard/`
   (версия поднята до 1.11 за переезд; попутно починен рассинхрон шапки и футера),
   тест-сторож скрепляет ожидаемую CLI версию с версионным футером стандарта, внешний
   репозиторий — вместе с соседней записью и её пинами — упразднён. Метка
   `dev-standard vX.Y` в шапках доков целевых реп — это *имя* стандарта и не менялась.
4. **У десктопа — кнопка починки.** «Обновить ссылки установки» в панели «Сейчас»
   перезапускает установщик через сайдкар; если `devst.exe` не рядом с `devst-ui.exe`,
   отдельный баннер говорит ровно это (деплой одной папкой) вместо сырых ошибок процесса.

## Последствия

- Пересборка и проверка сборки больше не могут задеть живой пайплайн; сборка больше не
  борется с работающим экзешником за собственную выходную папку.
- Свежая установка чиста по построению: вшиваются только пути экзешника пользователя —
  нечему гнить ссылками на чекауты и внешние репозитории.
- Стандарт и его CLI теперь версионятся вместе, под тестовым сторожем.
- Ручной деплой — осознанно: напоминание «канон устарел» сверяет канон с задеплоенным
  бинарём (путь берётся из маркера установки), а кнопка починки переустанавливает в два клика.
