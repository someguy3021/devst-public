# ADR-031: строка соседа в SessionStart (vaultify)

> Русский · [English](../../decisions/adr-031-neighbor-line-in-session-start.md)

> **Статус:** Принято · **Дата:** 2026-10-18
> **Суть:** SessionStart-хук показывает одну строку с состоянием соседнего инструмента
> (его доска задач / открытый handoff), когда тот установлен в тот же харнесс; детект —
> по собственному маркер-файлу установки соседа; любая проблема на стороне соседа
> молча опускает строку.
> **Связанное:** [ADR-012](./adr-012-integrations-install-doctor.md) (откуда берутся
> маркеры установки) · [vaultify](https://github.com/someguy3021/vaultify-public) —
> соседний инструмент, собранный по тем же стандартам (общая память ИИ-агентов, доска
> задач, поиск по Obsidian vault'ам)

## Контекст

devst в харнессе не один: автор запускает соседние инструменты, собранные по тому же
образцу (ноль зависимостей, CLI + десктоп-приложение, та же документационная
дисциплина). Один из них, **vaultify** — общая память ИИ-агентов, доска задач и поиск
по Obsidian vault'ам — держит состояние, полезное агенту на нулевой секунде сессии
(открытые задачи, открытый handoff). Жёстко привязывать devst к соседу против
духа проекта: devst обязан работать (и стартовать), даже когда ничего больше не
установлено.

## Решение

1. В канонический хук `devst-session-start.sh` добавлен блок «сосед»: если существует
   маркер установки соседа (`~/.zcode/vaultify.json`, его пишет собственный
   `integrations install` соседа), хук спрашивает соседа о состоянии
   (`vaultify status --json`) и добавляет к сообщению сессии **одну строку**, например
   `vaultify: board 3/12/1; open handoff H-0042`.
2. Полная деградация: нет маркера, нет CLI, таймаут 10 секунд, невалидный JSON —
   строки нет, и старт сессии никогда не ломается (тот же принцип «никогда не ломай
   старт сессии», что и у остального хука).
3. Обратное направление живёт в самом соседе: `status`/`doctor` vaultify детектят
   установленный devst по *его* маркеру (`~/.zcode/devst.json`) и показывают строку
   devst в ответ. Каждый инструмент детектит соседа по собственному маркеру соседа —
   без общих конфигов и связности.

## Последствия

- Контракт хука не меняется (валидный JSON, `suppressOutput`); строка аддитивна, так
  что контрактные тесты (`toContain`) проходят как были.
- Машины без соседа получают хук, байт-в-байт идентичный прежнему.
- Отложено: показ собственных задач devst на доске соседа (кандидат в бэклоге
  интеграции).
