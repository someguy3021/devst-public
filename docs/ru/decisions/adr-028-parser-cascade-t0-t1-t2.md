# ADR-028: каскад парсеров код-интеллекта (T0/T1/T2) и вшитые ассеты

> Русский · [English](../../decisions/adr-028-parser-cascade-t0-t1-t2.md)

> **Статус:** принято · **Дата:** 2026-10-09

**Суть:** точность графа кода — каскадом тиров: T0-сканер (свой, все языки, низкая
уверенность) → T1 LSP-мост (tsserver проекта; слот зарезервирован, реализации пока
нет) → T2 — парсеры-ассеты, вшитые в SEA-бинарь (tsc + набор @lezer + php-parser +
luaparse + lezer-elixir, ~10 МБ суммарно), с версионной честностью; индекс —
`.devst/graph.db`, вне docs/.

**Отвергнуто:** только T0-регэксп-сканер (шум от комментариев/строк, многострочные
блоки); полные tree-sitter-WASM-грамматики сейчас (web-tree-sitter в SEA не проверен —
отложено до hands-on); всё в бандле CLI (слоты нельзя ни выключить, ни пропустить);
полная семантика tsc (Program с проверкой типов файл-графу не нужен).

**Связанное:** [фича 10](../features/10-code-intelligence-clean-room.md) (решения
автора 6–7 за каскадом) · [ADR-018](./adr-018-sea-binary-distribution.md) (прецедент
вшитых ассетов) · [ADR-023](./adr-023-public-docs-only-release.md) (docs-only-релиз →
только пермиссивные лицензии) · [ADR-010](./adr-010-detect-dont-block.md) (фичи-гейты) ·
[ADR-017](./adr-017-hybrid-storage-md-sqlite.md) (SQLite) · repowise (публичный
проект, чей код-интеллект вдохновил clean room)

## Контекст

Фаза 3.1: граф кода и blast-radius для агентов. Этап 2а дал T0-сканер — регэкспы
не отличают комментарии и строки от кода («import x» внутри комментария = ложное
ребро), и точность упирается в потолок. Решения автора №6–7 (записаны в
[фиче 10](../features/10-code-intelligence-clean-room.md)): каскада из
сканера-фоллбека, LSP-моста как основы и вшитых компиляторов, «с версионной
честностью — чтобы я понимал, что что-то пошло не так, в момент когда смотрю»;
«кто лёгкий по размеру — захватить; сразу заложить, что их несколько». Ограничения:
SEA-бинарь самодостаточен (у потребителя нет node_modules), zero runtime-deps,
нативные .node в SEA нельзя, лицензии — только пермиссивные (docs-only-релиз,
[ADR-023](./adr-023-public-docs-only-release.md)).

## Опции

### A. Всё в бандле (import в src/, esbuild бандлит)

- Плюсы: нет загрузчика, нет ассетов.
- Минусы: слот нельзя ни выключить, ни не поставить (нет состояния «unavailable»),
  размер бандла всегда максимальный, версии парсеров не отделить от версии CLI,
  честность «кто на самом деле смотрел в файл» теряется.

### B. tree-sitter + WASM-грамматики (путь repowise)

- Плюсы: 40+ языков за одним рантаймом.
- Минусы: web-tree-sitter в SEA не проверен (грузит .wasm по пути; в SEA — только
  байты ассета через locateFile/instantiate; hands-on не сделан); +0,4 МБ рантайм
  и по 0,2–4 МБ на грамматику.

### C. Вшитые CJS-ассеты + Function-загрузчик (выбрано)

- Плюсы: каждый слот опционален и знает свою версию; SEA-механика уже есть
  ([ADR-018](./adr-018-sea-binary-distribution.md), канон вшит так же); CJS-дистрибутивы
  есть у всех пакетов; загрузка текстом через `new Function` — без data:-URL и без
  сети; лицензии вшиваются рядом с кодом (гигиена
  [ADR-023](./adr-023-public-docs-only-release.md)).
- Минусы: exe растёт ~10 МБ (прецедент 8 МБ уже принят); Function-загрузка — свой
  require-шим (мапа @lezer/lr+common → грамматики).

## Решение

**Вариант C.** Каскада: T0 включён всегда (база и фоллбек,
`engine=scanner/confidence=low`); T2-слоты по языку — если вендорный ассет доступен
и фича code-graph не off:

| Тир | Что это | Покрытие | engine / confidence |
|---|---|---|---|
| T0 | свой паттерн-сканер поверх вычищенного текста | все языки | `scanner` / low |
| T1 | LSP-мост (tsserver проекта) | TS/JS | слот зарезервирован, реализация — поздний этап |
| T2 | парсеры-ассеты, вшитые в SEA-бинарь | TS/JS (tsc, честный AST); Python, Go, Java, Rust, C++, Elixir (@lezer, вычистка); PHP (php-parser, полный AST); Lua (luaparse, полный AST) | `bundled` / high для tsc |

- **tsc (TS/JS):** `ts.createSourceFile` — честный AST-обход
  (import/export/require/dynamic-import), `engine=bundled/confidence=high`.
- **@lezer/{python,go,java,rust,cpp} + lezer-elixir:** v0-приём «точного лексера» —
  по дереву парсера вычищаются комментарии/строки (длины сохранены), затем T0-паттерны
  поверх чистого текста; один обходчик обслуживает все Lezer-языки.
- **php-parser, luaparse:** полные AST (CJS), тот же эффект — вычистка плюс
  T0-паттерны.
- **Версионная честность:** вшитая версия (манифест вендора) сверяется с версией
  проекта (`node_modules/typescript/package.json`); расхождение — никогда не тихий
  пропуск: статус `version-mismatch` кричит в `_meta` (degraded), файл помечен
  parsed-with-mismatch.
- **Слияние каскады:** спецификаторы дедупятся по (raw, kind); приоритет T2 над T0;
  ребро несёт engine/confidence лучшего тира, который его дал.
- **Вендоринг:** слоты вендорятся скриптом `pnpm vendor` (devDependencies →
  `vendor/parsers/`); манифест `vendor/parsers/manifest.json` (пакет / версия /
  лицензия / файл / размер) — генерируется, не пишется руками; в SEA вшивается
  walk'ом по каталогу, как канон ([ADR-018](./adr-018-sea-binary-distribution.md)).
- **Фичи-гейт:** `features.code-graph = off` — analyze/blast честно отказывают
  с причиной (первое живое применение рамки фичи-гейтов
  [ADR-010](./adr-010-detect-dont-block.md)).

## Обоснование

- Вариант C закрывает «их несколько» архитектурно: слоты — данные (манифест),
  а не код-ветки; добавление языка = строка манифеста + файл ассета + ветка вычистки.
- Версионная честность реализуется механически: манифест фиксирует вшитую версию,
  проектная версия читается из node_modules, расхождение становится статусом в `_meta`.
- B отложен осознанно: WASM-подслот — та же слот-архитектура; врата — hands-on
  SEA-проверка.

## Последствия

**Позитивные:** analyze перестаёт врать на комментариях/строках; TS/JS — точный AST;
слоты расширяемы без релиза ядра-логики (vendor-скрипт); лицензионная гигиена
docs-only-релиза — копии лицензий едут в ассетах.

**Негативные / риски:** exe +~10 МБ; Function-загрузчик обходит import-граф —
требование к вендоримым пакетам: быть standalone-дистрибутивами, require-мапа только
для @lezer/*; Lezer-приём v0 («вычистка + T0-паттерны») — не полный AST: символьный
уровень для не-TS языков потребует настоящих обходчиков.
