# ADR-015: Tauri UI-стек — Vite + Quasar webview, KernelAdapter

> Русский · [English](../../decisions/adr-015-tauri-ui-stack.md)

> **Статус:** принято · **Дата:** 2026-09-10

**Суть:** Tauri v2-окно devst: фронт — Vite + Vue 3 + Quasar через `@quasar/vite-plugin`
(без Quasar CLI) + vue-dnd-kit/core; чистое ядро `src/` исполняется прямо в webview;
мутации канона — чистые apply-трансформеры ядра, запись через `tauri-plugin-fs` со
scope на каталог репы; UI отделён от ядра интерфейсом KernelAdapter (сегодня прямой
импорт, после этапа 2.3 — сайдкар-IPC без правки экранов).

**Отвергнуто:** Quasar CLI (второй слой сборки поверх Vite); мутации через CLI/сайдкар
на старте (сайдкара нет, до него нужен Node — ломает «один exe»); Rust-команды в
бэкенде (перепись ядра на второй язык); Electron — только запасной план (портативность).

**Связанное:** [фича 03](../features/03-devst-ui-desktop-window.md) · roadmap 2.2.1 / 2.3 · [ADR-001](adr-001-ts-repo-instead-of-script.md)

## Контекст

Roadmap 2.2.1 (требования автора): реестры/чек/окружение — таблично-визуальные данные,
линейная консоль им вредят; выбор файлов для заморозки — «протыкать», не «печатать
глобы». No-install — один exe на любом диске; Хром для тулзы не открывать (Tauri =
системный WebView2, отдельный процесс, сессию Хрома не трогает); фронт — Vue («наш
стек»); UI — вид/редактор markdown-канона, не второй источник правды. Ядро src/ уже
чистое (212 тестов) — его можно исполнять где угодно, включая webview.

## Опции

### A. Quasar CLI + Tauri как обёртка (beforeDevCommand: `quasar dev`)

- Плюсы: привычный цикл `quasar dev`.
- Минусы: два CLI-слоя, дублирование конфигов (quasar.config + tauri.conf),
  гайды Tauri заточены под чистый Vite.

### B. Мутации через CLI `--json` / сайдкар

- Плюсы: единая точка мутаций, UI физически не разъедется с CLI; сайдкар — тот же
  артефакт, что и дистрибуция (2.3).
- Минусы: сайдкара нет; до него UI требует установленного Node (ломает «один exe»);
  каждый вызов — spawn процесса (на Windows дорого).

### C. Rust-команды в Tauri-бэкенде

- Плюсы: строгая граница доверия; git2-rs без системного git.
- Минусы: ядро переписывать или дублировать на Rust — два языка, 212 тестов мимо,
  дольше всех до MVP.

## Решение

**Вариант — Vite + Quasar-плагин, ядро в webview, KernelAdapter** (решения автора
2026-09-10, протокол — фича 03 §3):

1. Стек: Tauri v2 + Vite + Vue 3 + Quasar (`@quasar/vite-plugin`, НЕ Quasar CLI)
   + vue-dnd-kit/core для DnD freeze-панели.
2. Ядро src/ бандлится во фронт и вызывается как функции; git — системный через
   shell-плагин.
3. Мутации: сценарии выделяются из cli.ts в ядро как чистые apply-трансформеры
   («действие → список файловых записей {путь, текст}»); запись — tauri-plugin-fs,
   capabilities со scope на каталог открытой репы.
4. KernelAdapter — контракт UI ↔ ядро: DirectKernel (прямой импорт) сейчас,
   SidecarKernel (этап 2.3) позже — экраны не меняются.
5. Структура: pnpm workspace, папка `ui/` со своим package.json; CLI-пакет остаётся
   zero-runtime-deps. Walking skeleton — экран «Сейчас» + check-список.

## Обоснование

- Требования «один exe без Node», «Хром не трогаем» и реиспользование ядра выполняет
  только связка «ядро в webview + fs-плагин».
- KernelAdapter страхует главный минус этой связки (мутации живут в webview):
  сайдкар подменит реализацию адаптера, не экраны — вариант B становится апгрейдом,
  а не развилкой.
- Рефакторинг apply-трансформеров полезен и CLI: одна логика мутаций в ядре, cli.ts
  тоньше.

## Последствия

**Позитивные:**
- Скорость: ядро в том же процессе, без spawn/IPC на каждый чих; тесты ядра
  продолжают работать.

**Негативные / риски:**
- Rust-тулчейн: на машине автора rustc 1.62 (2022), Tauri v2 требует ≥1.77 —
  этап 0 фичи 03 (rustup update, MSVC Build Tools, WebView2).
- Фронт получает ФС-доступ — режется scope-capability на каталог репы.
- Системный git как зависимость exe (для «звёздочек» — git2 в сайдкаре).
- В бандл UI идут только браузер-совместимые модули ядра; часть «чистых» модулей
  использует node:* (visual, png, integrations) — они UI не нужны, но правило
  гигиены «новые чистые модули без node:*» надо зафиксировать (фича 03 §7).
