# ADR-016: UI E2E — MockKernel + Playwright в браузере

> Русский · [English](../../decisions/adr-016-ui-e2e-mockkernel-playwright.md)

> **Статус:** принято · **Дата:** 2026-09-10

**Суть:** автотесты UI — настоящим Chromium против vite-сборки с MockKernel
(in-memory KernelAdapter); tauri-driver остаётся отложенным до стабильного exe.

**Отвергнуто:** tauri-driver сейчас (тяжело, UI мигрирует); только компонентные
тесты (не покрывают сценарии); не покрывать UI вовсе (баг DnDProvider — образец).

**Связанное:** [ADR-015](adr-015-tauri-ui-stack.md)
(§6 KernelAdapter) · [фича 03](../features/03-devst-ui-desktop-window.md) · roadmap 2.2.1

## Контекст

Экраны Tauri-окна (этапы 0–4) не имели автотестов: чистые хелперы покрыты
юнит-тестами, но компоненты/сценарии — только ручной живой проверкой.
Регресс-баг этапа 3 (тег `<DndProvider>` вместо `DnDProvider`) не ловится ни
vue-tsc (Quasar ослабляет резолв компонентов), ни юнит-тестами — ловится только
поведенческим прогоном. Нужен автоматический поведенческий слой сейчас, не после
этапа 6.

## Опции

### A. tauri-driver (WebDriver) против exe

- Плюсы: полный стек, включая Tauri-оболочку.
- Минусы: WebDriver-бинарники на каждую платформу; UI ещё мигрирует (этапы 5–6) —
  тесты будут чинить чаще, чем они ловят; exe ещё нет.

### B. Компонентные тесты (@vue/test-utils)

- Плюсы: дёшево, быстро.
- Минусы: монтирует компоненты поодиночке — сценарии «открыл репу → мутация →
  записалось» не покрывает; всё равно нужен мок-адаптер.

### C. Playwright в обычном браузере + MockKernel

- Плюсы: настоящая сборка UI, настоящие сценарии; Playwright уже в devDeps
  (visual-e2e); контракт KernelAdapter (ADR-015 §6) именно про подмену
  реализаций — MockKernel встаёт рядом с DirectKernel без правки экранов;
  Tauri-API не нужны вовсе.
- Минусы: Tauri-оболочка (диалоги, плагины, окно) не покрыта; MockKernel едет в
  бандле (мелкий, отключён флагом `__TAURI_INTERNALS__`).

## Решение

**Вариант C.** Фабрика `ui/src/kernel/index.ts`: в webview (есть
`__TAURI_INTERNALS__`) — DirectKernel, в обычном браузере — MockKernel
(in-memory ФС, пути относительно root, журнал reveal-вызовов). Для e2e — крюк
`window.__devstMock` (setFiles/getFiles/revealCalls). Сценарии — `tests/ui-e2e.test.ts`
(vitest + chromium): vite dev на фиксированном порту, фикстура-репа с
детерминированным каноном (ровно 2 ошибки линта, стухший штамп env), страница
открывается заново на каждый тест.

## Обоснование

- ADR-015 заранее сделал адаптер точкой подмены; SidecarKernel (2.3) сядет в ту
  же фабрику — решение «на вырост», а не одноразовый хак.
- e2e поймал реальный баг рефакторинга фабрики (забитый вызов `existingPaths`
  со старым идентификатором — канон считался без существующих путей) раньше
  typecheck.

## Последствия

**Позитивные:**
- 7 поведенческих сценариев всех экранов в `pnpm test`; мутирующий сценарий
  freeze-реестра проверяется по содержимому mock-ФС.
- Прецедент подмены адаптера — прямая дорога SidecarKernel (2.3).

**Негативные / риски:**
- Tauri-оболочка не покрыта — smoke остаётся ручным до этапа 6 (потом
  tauri-driver, если понадобится).
- Селекторы завязаны на тексты/классы Quasar — правки копирайтинга могут
  ломать тесты (осознанно: это и есть пользовательский контракт).
