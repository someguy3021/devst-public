# ADR-024: Бюджеты линта 250 и 20, override devst:allow, лог-кампании с Дополнениями

> Русский · [English](../../decisions/adr-024-lint-budgets-250-20-200.md)

> **Статус:** Принято (T-30) · **Дата:** 2026-10-05 · замещает [ADR-004](adr-004-log-budget-200.md)

**Суть:** лог 200→250, шапка 15→20, карта 120→200; осознанный перелёт бюджета —
комментарием `<!-- devst:allow правило: причина -->`; многодневная сессия ведётся как
«лог-кампания» с секциями «## Дополнение N (ГГГГ-ММ-ДД): заголовок» (бюджет — на
секцию, не на файл).

**Отвергнуто:** поднять все бюджеты разом (лечит TTRPG-кейс, но убивает токен-экономию
L0 для малых реп — перелёты должны быть подписаны автором, а не нормой); добавить жанр
«кампания» как отдельный тип файла (дубль механизма сессий, а решаемая проблема —
аппенд в одну запись).

**Связанное:** [ADR-004](adr-004-log-budget-200.md) (прошлое поднятие 60→200 —
замещён) · T-29 (кросс-репо сверка — та же боль, «Связанное» с соседними репами в
шапках) · внешний TTRPG-проект (30 warn из check — 28 осознанных «сверх» по запросу
автора, сигнал заглушен).

## Контекст

Прогон по внешнему TTRPG-проекту (2026-10-05): 0 ошибок, 30 предупреждений, из них
~28 — осознанные перелёты бюджетов по явной просьбе автора («пиши сверх, если смысл
режется»). Итог: предупреждения перестали нести сигнал — среди них тонут реальные
(шапка-плейсхолдер, окружение-свежесть). Три узких места:

1. **Лог ≤ 200**: 11 логов сверх, до 1245 строк — многодневные кампании ИИ-генерации
   живут как одна запись-накопитель с «Дополнениями» (в session-114 — 18 штук),
   а стандарт моделирует «1 сессия = 1 запись 60–80 строк». Строгая посессионность
   ещё и блокирует параллельную работу в одной репе: некуда аппендить продолжение
   кампании.
2. **Шапка ≤ 15**: 17 доков сверх — шапки-конспекты (L1 «читай шапку вместо тела») и
   богатые блоки «Связанное».
3. **Карта ≤ 120**: 162/120 при ~190 md-файлах — «1 строка = 1 док» не влезает
   арифметически. Решение автора (2026-10-05, там же где 250/20): бюджет карты —
   **200**; группировка ADR по темам (>15 ADR) остаётся рекомендацией текстом,
   `devst:allow` — запаской свыше 200.

## Решение

**Бюджеты (линт):**
- `лог-длинный`: 200 → **250** для обычной записи (рекомендация «целись в ~60–80» —
  по-прежнему текст).
- `шапка-длинная`: 15 → **20**.
- `карта-длинная`: 120 → **200** (при ~100+ доках «1 строка = 1 док» не влезает в 120;
  перебор сверх 200 — резать описания, allow — осознанный запас).

**Override `devst:allow` (семантика dev-standard ADR-029, как eslint-disable):**
- Формат: `<!-- devst:allow <правило>[: причина] -->` в любом месте дока (для карты —
  в `docs/README.md`).
- Действует только на бюджетные warn-правила: `карта-длинная`, `шапка-длинная`,
  `лог-длинный`, `дополнение-длинное`. Error-правила и остальные warn — не допускаются.
- Сработавший allow не попадает в warnings: выводится строкой `• [допущено]` и в
  `--json` как `allowed` — перелёт остаётся видимым, но отделён от сигнала.
- Гигиена: allow без сработавшего правила → warn `override-лишний`; allow небюджетного
  правила → warn `override-неизвестный`.

**Лог-кампания (запись-накопитель), формат set in stone:**
- Файл именуется как обычная сессия; продолжения НЕ заводят новых файлов — дописываются
  секции.
- Секция продолжения: `## Дополнение N: заголовок`, где N — номер по порядку аппендов
  (пропуски легальны), а дата ГГГГ-ММ-ДД стоит где угодно в строке заголовка — обычно
  в скобках сразу после номера: `## Дополнение 12 (2026-10-04, примечание): заголовок`.
- Хоть одно «Дополнение» в файле = декларация формата: общий бюджет лога к файлу не
  применяется (override не нужен), вместо этого:
  - бюджет **секции** — те же 250 строк (`дополнение-длинное`);
  - дубликат номера — warn `дополнение-нумерация` (пропуски легальны: параллельные
    аппенды);
  - заголовок «Дополнение…» не по формату — warn `дополнение-формат`.
- Шапка/Суть проверяются как у обычной записи.

## Обоснование

- Перелёт бюджета — легитимное решение автора, но оно должно быть **подписано**: allow
  возвращает линтеру способность докладывать «а вот это не задумано».
- Формат-как-декларация для кампаний лучше отдельного allow: заголовок «Дополнение N
  (дата)» сам документирует намерение, и линтер может проверять гигиену формата.
- Бюджет 250 универсален: и на обычный лог, и на одно Дополнение — одно число, меньше
  магии.

## Последствия

**Позитивные:**
- TTRPG-кейс: из 30 warn остаются ~2 настоящих (плейсхолдер, свежесть окружения);
  остальное — осознанные allow или легальные кампании.
- Параллельная работа в одной репе: второй агент аппендит своё «Дополнение N+1» без
  конфликта жанров (пропуски номеров легальны).
- Многодневная история кампании не режется и не разъезжается по N файлам сессий.

**Негативные / риски:**
- Кампания может разрастись неограниченно (каждая секция ≤ 250, число секций не
  ограничено) — считаем фичей: это журнал, а не L0-док; карта log/ не перечисляет.
- `override-лишний` добавит шум в момент, когда перелёт «уже не перелёт» — это
  намеренно: подпись должна быть снята, когда нужда отпала.
