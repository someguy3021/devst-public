# ADR-009: LLM-аудит шапок — команда + напоминание раз в месяц

> Русский · [English](../../decisions/adr-009-llm-audit-of-heads.md)

> **Статус:** принято · **Дата:** 2026-09-08

**Суть:** `/docs-audit` сверяет шапки доков architecture/features с их телами;
SessionStart-хук напоминает раз в 30 дней по метке `_Аудит шапок: дата_` в
docs/README.

**Отвергнуто:** авто-прогон по расписанию (токеноёмко — жёсткое требование автора);
аудит всех доков (ADR/roadmap/log жёстко форматированы, их держит в форме линтер);
метки на каждый док (шум).

**Связанное:** [ADR-003](adr-003-harness-integrations.md) · [ADR-008](adr-008-standard-version-tracking.md)

## Контекст

Слабость №2 из ревизии: линтер проверяет форму шапок доков, а не содержание —
строка «Суть» может отстать от тела. Все четыре вопроса автора закрыты
рекомендованными вариантами: триггер «команда + напоминание», охват
«architecture + features», полномочия «мелочи чинит сам + отчёт», метка «строка
в docs/README».

## Решение

Slash-команда `/docs-audit`: сверяет Суть / Ключевые факты / Обновлено / Связанное
с телом; мелочи правит сама, спорное докладывает списком на утверждение; в конце
обновляет метку и гонит check. SessionStart-хук: метки нет → мягкое напоминание;
старше 30 дней → «не делался N дней». Метка живёт сразу после панели «Сейчас».

## Последствия

Стоимость: один прогон покрывает ~15–25 доков, только по запросу; напоминание —
одна строка в systemMessage (токенов агента не ест — в транскрипте подавлено).
Отсутствие метки напоминает о себе до первого аудита — сознательная мотивация.
