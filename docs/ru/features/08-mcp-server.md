# Feature 08: MCP-сервер — типизированный агентный доступ к канону и реестру

> Русский · [English](../../features/08-mcp-server.md)

> **Статус:** Read-only поверхность реализована (23 инструмента) · **Обновлено:** 2026-10-10

**Суть:** подкоманда `devst mcp` поднимает локальный MCP-сервер (stdio, JSON-RPC,
zero runtime-deps, на базе SEA-бинаря) и даёт агентам любых харнессов
типизированный доступ к канону: панель «Сейчас», реестр задач, ADR, карту доков,
связи соседей. Read-only был первым этапом; мутации — отдельный этап за гейтом,
с обязательной атрибуцией актёром ([фича 09](./09-actors-and-roles.md)).

**Ключевые факты:**

- 23 инструмента покрывают агентную поверхность CLI: гигиена/канон
  (`get_map/brief/reminders/uncommitted/undocumented/features`, `check_docs`),
  реестр и окружение (`get_panel/board/task/decisions/links/env/audit`),
  код-интеллект (`analyze`,
  `get_overview/context/blast_radius/risk/health/history/symbols/file`).
- Транспорт — stdio JSON-RPC 2.0 (newline-delimited); сервер живёт ровно столько,
  сколько жива сессия харнесса — без демона, без сети. Источники правды (docs/ и
  реестр) читаются на каждом вызове: кэша нет — протухать нечему.
- Каждый ответ в `_meta`-конверте — свежесть/полнота/усечения; подсказка
  `_meta.stale_warning` толкает агента перезвать `devst analyze`.
- Реализация — stdlib Node, без SDK (`src/mcp-run.ts`); сбор фактов общий с CLI
  (`src/collect-run.ts`) — один источник, без дублей. Проводка —
  `devst integrations install --mcp` с проверкой `doctor`.

## Сценарии

1. Агент начинает задачу → `get_panel` + `get_board` → видит фазу, горячее и
   свои задачи без ручного чтения README.
2. Агент встречает ADR-ссылку → `get_decisions` → шапки решений с датами
   (а после [фичи 09](./09-actors-and-roles.md) — и с подписантами).
3. Агент заканчивает работу → `check_docs` → машинный отчёт линта с `_meta`
   (свежесть против HEAD) — вместо парсинга цветного вывода консоли.
4. Сессия в Claude Code или Codex (не zcode) → тот же `devst mcp` из их
   стандартного MCP-конфига, установленного `devst integrations install --mcp`.
   Канон перестаёт быть zcode-эксклюзивом.
5. (Этап 3, впереди) Агент закрывает задачу → `close_task` с `actor=@id` —
   запись идёт через то же чистое ядро, что и CLI; параллельный агент не видит
   «database is locked» (предусловие: busy_timeout).

## Решения дизайна

### stdio, без кэша, без демона

Сервер живёт ровно столько, сколько жива сессия харнесса. Без демона, без
индекса, без сети — принцип «выездного инструмента». Источники правды читаются
на каждом вызове: кэша нет, значит нечему протухать (урок нестабильности
MCP-серверов с индексом). Реализация — только stdlib; MCP-слой — ещё одна тонкая
обвязка рядом с `cli.ts`, чистые ядра не тронуты.

### Имена «вопрос → инструмент», строго read-only первым этапом

Имена инструментов следуют шаблону `get_*` — вопрос ложится на один инструмент
(урок внутренней разведки публичных агентных тулз). Первый этап — строго
read-only; мутации — отдельный этап за гейтом. Имя `analyze` совпадает с
CLI-командой намеренно: подсказки `_meta.stale_warning` («индекс отстал —
devst analyze») толкают агентов звать тул с этим самым именем — реальные
агентные сессии показали, что подсказка работает. `analyze` — единственный
мутатор среди инструментов, и пишет он только производный код-индекс
(`.devst/graph.db`), не канон; мутации канона остаются за гейтом этапа 3.

## Не делаем

- Не SSE/HTTP-транспорт и не сетевой доступ — только локальный stdio.
- Не ресурсы/prompts-поверхности MCP и не LLM-обогащение ответов — lean-профиль.
- Не замена хуков/скилла/CLI: ритуалы сессий остаются за человеком-в-петле;
  MCP — слой данных для агентов.
- Не distill/сжатие выводов — ответы и так малы.

## Этап 3 (впереди): мутации за гейтом

`new_task`/`close_task` с обязательным `actor=@id`
([фича 09](./09-actors-and-roles.md)), сериализация записи (busy_timeout),
staging для параллельных агентов
([ADR-022](../decisions/adr-022-parallel-agents-staging-join.md)).
