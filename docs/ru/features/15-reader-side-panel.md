# Feature 15: ридер — боковая панель чтения файлов в десктоп-приложении

> Русский · [English](../../features/15-reader-side-panel.md)

> **Статус:** Реализовано (ядро и основные точки входа; два пункта ТЗ в ожидании: ленивый рендер тяжёлого контента, точка входа из дерева заморозки) · **Обновлено:** 2026-10-24
> **Суть:** правая панель-ридер в десктоп-приложении devst: любой путь в UI — объекты
> задач, файлы правил чек-листа, ссылки журнала, фича-доки — кликается и открывается
> справа, не покидая экрана. Markdown рендерится, код — с нумерацией строк, картинки
> и PDF — сразу. Цель: **человек верифицирует, читая сами документы, а не названия
> файлов.**
> **Ключевые факты:**
> - Построен под [фичу 14](./14-spec-items-as-data.md): подтверждать пункт ТЗ, не читая
>   сделанное, — ровно тот фейл, который убирает ридер.
> - Роутер контента: `.md` → отрендеренный markdown; текст/код → моноширинно с
>   нумерацией строк; png/jpg/gif/svg/webp/pdf → рендер через data-URL; остальное —
>   заглушка с «копировать путь» и «открыть в редакторе».
> - Файлы больше ~400 КБ показывают первые 2000 строк с плашкой «показано частично».
> - Read-only по решению; в хедере — «копировать путь» и «открыть в редакторе» (reveal).
> **Связанное:** [фича 03](./03-devst-ui-desktop-window.md) (десктоп-окно, в котором живёт ридер) ·
> [фича 14](./14-spec-items-as-data.md) (главный потребитель: верификация пунктов ТЗ) ·
> [ADR-016](../decisions/adr-016-ui-e2e-mockkernel-playwright.md) (браузерный E2E, покрывающий ридер)

## Сценарии

1. **Верификация (главный).** Пункт фичи помечен «сделано» → в карточке инбокса человек
   кликает объект или фича-доку → ридер рендерит markdown справа → выбирает ступень,
   не покидая экрана.
2. **Чек-лист.** Проваленная конвенция показывает файл правила → клик открывает его
   в ридере в нужном месте.
3. **Задачи и журнал.** Объекты/связанные файлов задач и ссылки журнала — кликабельные
   чипы; относительные `.md`-ссылки внутри открытого markdown открываются тем же
   ридером — маленький док-граф по кликам.
4. **Бинарник** (png, pdf) рендерится сразу; непонятное получает «открыть в редакторе»
   плюс «копировать путь».

## Детали поведения

- Сплиттер: минимум 240 px, максимум 65 % окна; ширина переживает перезапуски; `Esc`
  закрывает панель.
- Навигация: стек назад/вперёд с breadcrumbs — проверка цепочки документов не теряет путь.
- Панель и приложение скроллятся независимо — скролл списка задач никогда не двигает ридер.
- Ридер исполняет то же чистое ядро в webview ([ADR-015](../decisions/adr-015-tauri-ui-stack.md));
  браузерный E2E-сьют покрывает рендер, внутренние ссылки и историю навигации на фикстуре
  `MockKernel`.

## НЕ-цели

- Не редактирование (read-only + «открыть в редакторе» вместо него).
- Не поиск по файлам и не дерево-браузер внутри ридера.
- Не аннотации office-форматов и PDF, не diff-вью — возможно позже, по спросу.
- Два пункта ТЗ честно в ожидании: тяжёлый контент рендерится сразу (без ленивого
  монтирования при схлопнутой панели и во время resize), а дерево заморозки открывает
  меню, а не ридер.
