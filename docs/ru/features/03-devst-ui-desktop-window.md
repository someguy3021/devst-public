# Feature 03: devst UI — настольное окно (Tauri)

> Русский · [English](../../features/03-devst-ui-desktop-window.md)

> **Статус:** В работе (этапы 0–6 сделаны; остались 3b figma-рендеры) · **Обновлено:** 2026-09-25
> **Суть:** настольное Tauri-окно к канону docs/, без Хрома: freeze-панель (дерево файлов × статусы, drag-and-drop, live-валидация глобов), check-список, env-таблица, панель «Сейчас» и закрытие сессии кнопкой. UI — вид/редактор markdown-канона, никогда не второй источник правды.
> **Ключевые факты:**
> - Стек: Quasar + Vue 3 + Vite через `@quasar/vite-plugin` (не Quasar CLI); `@vue-dnd-kit` для drag-and-drop; vue-i18n для локализации (ru — эталон, en).
> - Мутации идут через KernelAdapter: чистые трансформеры ядра превращают действие в список файловых записей; запись — за адаптером (tauri-plugin-fs с динамическим scope на каталог выбранной репы).
> - В webview бандлятся только браузер-совместимые модули ядра; модули node:* внутрь не попадают (WebCrypto-реализация за адаптером, если когда-нибудь понадобится хэширование).
> - Портативный одиночный exe: `tauri build --no-bundle` → один файл ~11 МБ с запечённым фронтендом; из окружения нужен только WebView2.
> - Поведенческий слой UI покрыт браузерным e2e с MockKernel (vitest + Chromium), а не tauri-driver.
> **Связанное:** [ADR-015: Tauri UI stack](../decisions/adr-015-tauri-ui-stack.md) · [ADR-016: UI e2e с MockKernel](../decisions/adr-016-ui-e2e-mockkernel-playwright.md) · [Feature 01: Baseline-скриншоты](./01-baseline-screenshots.md) · [Feature 02: Bug Hunt](./02-bug-hunt.md) · roadmap 2.2.1 · список open-questions («хранение данных» — первый в очереди)

## 1. Суть и потребители

| Потребитель | Как пользуется |
|---|---|
| Автор (ежедневно) | видит «Сейчас»/check без терминала; ведёт freeze-реестр, «протыкая» файлы; закрывает сессии формой |
| Будущие публичные пользователи | тот же фронт в вебе («на потом», roadmap 2.2.1) |

## 2. Сценарии

1. Открыл репу → окно показывает панель «Сейчас», ошибки/предупреждения check и свежесть штампа «Проверено» окружения.
2. Freeze-панель: дерево файлов проекта × статусы реестра; перетащил файл на 🔒 — строка реестра создана, глоб подсвечен live-валидацией; инспектор строки — области (блоки SFC/файл/глоб) и исключения.
3. Закрытие сессии: форма (суть, коммиты, что осталось) → создаёт log-запись, прогоняет map/status/check — всё из окна, без терминала.
4. (этап 3b) Рядом со строкой реестра — рендер figma-dump как эталон замысла (скрин — страж факта; принцип [фичи 01](./01-baseline-screenshots.md)).

## 5. Не-цели

- Своя БД/состояние как источник правды (забор roadmap 2.2.1; тема хранения — в open-questions, первая в очереди).
- Tauri-e2e автотесты (tauri-driver) — отложено до стабильного exe; поведенческий слой UI покрыт браузерным e2e с MockKernel ([ADR-016](../decisions/adr-016-ui-e2e-mockkernel-playwright.md)).
- Веб-версия — «на потом» (публичным пользователям).
- Запуск Playwright-прогонов из UI (visual остаётся в CLI/проектах).

## 6. KernelAdapter (контракт UI ↔ ядро)

- Чтение: `snapshot(root)` — чистые функции ядра (status/check/freeze/env) прямо в webview, никакого IPC.
- Мутации: `apply(action)` — сценарий как чистый трансформер «действие → список файловых записей {путь, текст}»; запись — за адаптером (сегодня tauri-plugin-fs).
- Реализации: DirectKernel (этапы 1–5), MockKernel (браузерный e2e, [ADR-016](../decisions/adr-016-ui-e2e-mockkernel-playwright.md)) → SidecarKernel (сайдкар 2.3) — подмена без правки экранов; выбор — фабрика `ui/src/kernel/index.ts` по флагу `__TAURI_INTERNALS__`.
- Сопутствующий рефакторинг: мутационные сценарии переезжают из cli.ts в ядро — полезно и для CLI (одна логика, тонкий cli.ts).

## 7. Ограничения ядра для webview

- В бандл UI идут только браузер-совместимые модули (кандидаты: util, head, sessions, env, check, map, status, brief, freeze, undoc — проверить на этапе 1).
- Модули с node:* (visual, png, integrations) в UI не попадают; если хэши понадобятся — WebCrypto-реализация за адаптером.
- Новое правило гигиены src/: чистые модули не тянут node:* (зафиксировать в AGENTS.md на этапе 1).

## 8. Тесты / DoD

- Apply-трансформеры — юнит-тесты в tests/ (vitest), как всё ядро.
- Live-валидация глобов — расширение юнит-тестов freeze.ts.
- Каждый этап: окно проверяется руками на репе devst (с этапа 3 — и на подопытной репе).
- Поведенческий слой (с сессии 11): браузерный e2e — vitest + chromium против vite-сборки с MockKernel, 7 сценариев по всем экранам (tests/ui-e2e.test.ts, [ADR-016](../decisions/adr-016-ui-e2e-mockkernel-playwright.md)).
- Tauri-driver — кандидат этапа 6 (стабильный exe).
