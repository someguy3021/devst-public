# Feature 09: Актёры и роли — кто принял решение, фиксируется на каждой сущности

> Русский · [English](../../features/09-actors-and-roles.md)

> **Статус:** Дизайн (не реализовано) · **Обновлено:** 2026-10-09

**Суть:** каждая сущность канона несёт «кто и в какой роли» — подписант ADR,
автор/исполнитель задачи, дизайнер за ui-freeze-закреплением, актёр-источник
требования, репортёр баг-карточки. Состав команды и роли живут в `docs/team.md`
(соло-случай вырождается честно: один актёр, проставляется автоматически).
Агент получает адресные эскалации: не «спроси автора», а «закрепил @designer —
эскалация дизайнеру».

**Ключевые факты:**

- роли — источники авторитета для агента, не ACL: принуждение остаётся у
  freeze-гардов и реестра;
- агенты — тоже актёры (роль «агент»): запись машины — всегда кандидат или
  факт-вход, пока не подписал человек («машина предлагает — человек принимает»);
- соло-режим платит ноль: единственный дефолт-актёр из devst.json проставляется
  автоматом;
- для команды это аудит-трейл («кто что решил и когда»), онбординг («вопросы
  дизайна — к X») и уход человека (его решения подсвечиваются на пересмотр).

**Связанное:** [ADR-013](../decisions/adr-013-default-deny.md) (default-deny →
адресные эскалации) · [ADR-014](../decisions/adr-014-req-reconcile.md)
(источники требований) ·
[ADR-017](../decisions/adr-017-hybrid-storage-md-sqlite.md) (миграция колонок
реестра) · [ADR-022](../decisions/adr-022-parallel-agents-staging-join.md)
(параллельные агенты как различимые актёры) · [фича 02](./02-bug-hunt.md)
(репортёр баг-карточек — зачаток) · [фича 05](./05-reminder-system.md)
(таргет-актёр напоминаний) · [фича 08](./08-mcp-server.md) (мутации
с `actor=@id`)

## Сценарии (замысел)

1. Агент правит файл под ui-freeze-закреплением → гард отвечает: «закрепил
   @designer (Имя, 2026-10-02) — эскалация дизайнеру, не владельцу репы».
2. Требование R-12 в requirements.md несёт «источник: @designer»; вердикт
   req-check подписывается проверявшим (агент или человек, с ролью).
3. Агент предлагает рефакторинг, конфликтующий с ADR → в ADR стоит «решение
   принял: @author» → агент эскалирует, а не молча переписывает.
4. Тестер заводит баг-карточку → карточка несёт репортёра @qa → агент отвечает
   «исправлено — сверься с @qa».
5. Дизайнер уходит из проекта → team.md закрывает его период → все закрепления
   и решения @designer подсвечиваются needs_review (устаревание по актёру).
6. Два актёра закрепили противоречащее (дизайнер «так», тестер «эдак») →
   не авто-резолюция, а вопрос-задача с упоминанием обоих.

## Дизайн в трёх ходах

Почему это расширение концепции, а не фича-остров: инвариант стандарта «решения
фиксируются дословно, номерами» уже требует подписанта — фича обобщает его с
«автор = единственный» до «актёр + роль из состава команды».

### Состав команды: `docs/team.md`

Новая секция стандарта: актёры с коротким латинским `@id`, именем, ролями
(автор / дизайнер / тестер / заказчик / наблюдатель / агент) и периодами
активности. Соло — одна строка; дефолт-актёр берётся из devst.json и
проставляется автоматически.

### Агент — актёр, но решением становится подпись человека

Записи агента — всегда кандидат или факт-вход; управляющим решением — только
после человеческой подписи. Параллельные агенты различаются как отдельные
актёры ([ADR-022](../decisions/adr-022-parallel-agents-staging-join.md)).

### Совместимость: новые поля шапок = изменение стандарта

«Решение принял:», «закрепил @id», «источник: @id» — новые поля шапок →
изменение dev-standard (пара ADR, поднятие версии, полный канон-синхрон:
скилл, шаблоны, фикстуры тестов). Реестр задач получает колонки
author/reporter/decider в SQLite (миграция
[ADR-017](../decisions/adr-017-hybrid-storage-md-sqlite.md)).

## План (четыре этапа, все впереди)

1. **Данные:** `docs/team.md` + дефолт-актёр в devst.json; поле подписанта в
   шапке ADR (`new adr` проставляет); колонки реестра; `task new --by @id`;
   чек знает поля.
2. **Эскалации:** гард ui-freeze отвечает адресно
   ([ADR-013](../decisions/adr-013-default-deny.md) получает «кого спрашивать»);
   напоминания получают таргет-актёра ([фича 05](./05-reminder-system.md)).
3. **Входы:** требования несут «источник: @id»
   ([ADR-014](../decisions/adr-014-req-reconcile.md)); баг-карточки — репортёра
   ([фича 02](./02-bug-hunt.md)); логи сессий — «вёл: @id (роль)».
4. **Жизнь состава:** периоды активности; needs_review по ушедшему актёру;
   агент-подписи в MCP-мутациях ([фича 08](./08-mcp-server.md), этап 3).

## Не делаем

- Не иерархия прав и не ACL: роли — источники авторитета для агента, не
  механика запретов (гейты остаются у freeze и реестра).
- Не авто-резолюция конфликтов ролей — только вопрос-задача.
- Не синхронизация с HR/корпоративными каталогами — `team.md` пишется руками.
