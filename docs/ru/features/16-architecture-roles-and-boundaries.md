# Feature 16: архитектурные роли и границы как данные

> Русский · [English](../../features/16-architecture-roles-and-boundaries.md)

> **Статус:** Реализовано (этапы 0–5: модель, чекер, пресеты, генерация канона, MCP, вкладка десктопа, ИИ-первая детекция; пункты ТЗ ждут человеческой верификации) · **Обновлено:** 2026-10-24
> **Суть:** архитектура репы становится машиночитаемой моделью в
> `docs/architecture/arch.model.json`: роли-классификатор путей (плоско или деревом),
> матрица рёбер **default-deny** (настраиваемо), правила пакетов, контракты узлов с
> severity и пресеты, унаследованные от официальных rulebook'ов. `devst arch check`
> сверяет граф импортов с матрицей; человекочитаемый канон (`02-arch-roles.md` +
> mermaid-диаграмма) — **генерируемая проекция**: ручные правки ничего не ломают, они
> обнаруживаются, и канон перегенерируется. «Не картинка — модель»: канон, диаграммы и
> дашборды — проекции одного источника.
> **Ключевые факты:**
> - Агент узнаёт границы с порога сессии: MCP `get_arch_model` возвращает роли, матрицу
>   и текущие нарушения; однострочная arch-строка («нужно расследовать») сидит в
>   `devst check` и brief сессии — detect, don't block ([ADR-010](../decisions/adr-010-detect-dont-block.md)).
> - Пресеты — по официальным rulebook'ам, clean-room: **FSD** (семь слоёв, импорты строго
>   вниз, public API на слайсах, исключение `@x` для кросс-импортов) и **Clean
>   Architecture** (правило зависимостей: entities ← use cases ← adapters ← frameworks);
>   плюс пустая заготовка.
> - Этап 0: tsconfig-алиасы в резолвере графа — без них FSD-репы (`@/entities/user`)
>   просто непроверяемы; неразрешённые алиасы честно помечаются.
> - `arch detect` — ИИ-первый: модель в сессии предлагает агент, машинные эвристики —
>   fallback. Агент не пишет в модель мимо человеческой верификации.

## Сценарии

1. **Конструктор.** `devst arch init --preset fsd` → модель появляется в
   `docs/architecture/arch.model.json` плюс сгенерированный канон `02-arch-roles.md` →
   автор правит её под себя (что-то разрешить, что-то запретить) в конструкторе
   десктопа или руками → `devst arch check`.
2. **Проверка.** `devst arch check` — каждое ребро импорта из графа кода сверяется с
   матрицей; контракты узлов проверяют public API, нейминг и запрещённые типы ассетов;
   каждое нарушение несёт файл, правило, «почему» и severity; человекочитаемый вывод
   плюс `--json`.
3. **Сессия агента.** Brief и `get_arch_model` передают роли, границы и текущие
   нарушения — агент пишет код «в границах», а не гадает, и сразу видит «нужно
   расследовать».
4. **Дрейф.** Автор правит модель → канон перегенерируется; ручная правка канона
   расходится с моделью → check ловит расхождение и предлагает перегенерацию. Ручные
   правки детектируются, а не теряются.

## Модель, коротко

- Роли: свой минимал-глоб без зависимостей, плоская и древовидная формы, дубль globs —
  ошибка конфигурации, приоритет = число литеральных сегментов.
- Рёбра: матрица default-deny (`defaultDeny: false` допустим на проект); циклы внутри
  роли — per-role флаг, решает rulebook.
- Пакеты: правила «роль → разрешённые внешние пакеты» с первого дня («без внешних
  пакетов современных проектов не существует»).
- Контракты узлов: public API (вход через `index.ts`), нейминг, запрещённые расширения
  ассетов; `severity: error|warn` на правило; флаг `slices` (FSD) запрещает
  горизонтальные импорты между соседними слайсами — нотация `@x` и есть легальное
  исключение.
- Golden-тесты: мини-репа FSD, где чистое дерево проходит, а каждая внесённая мутация —
  импорт вверх, горизонталь между слайсами, обход public API, запрещённый пакет,
  запрещённый ассет — даёт ровно своё нарушение.

## НЕ-цели

- Никакого копирования чужих дашбордов и кода — clean-room, только идеи из официальных
  rulebook'ов.
- Агент не пишет в `arch.model.json` мимо человеческой верификации.
- Правила на строки кода, офисные форматы, монореп-воркспейсы — v2, по спросу.
- Слияние вкладки «Arch» с «Код» в десктопе — открытое решение; пока живут раздельно.
