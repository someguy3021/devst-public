# Feature 01: Baseline-скриншоты замороженных экранов (freeze --baseline/--verify)

> Русский · [English](../../features/01-baseline-screenshots.md)

> **Статус:** Реализовано (этапы 1–3 плюс обязательные тесты) · **Обновлено:** 2026-09-09
> **Суть:** 🔒-заморозка фиксирует скриншоты реального экрана в наборе вьюпортов; дальше Playwright-диф механически ловит «верстка уехала» — регрессия верстки становится машинным фактом с контекстом заморозки, а не мнением агента.
> **Ключевые факты:**
> - Только скриншот-диф, не функциональные тесты; попиксельное сравнение с рендерами Figma запрещено принципиально (шрифты/сглаживание).
> - Baseline снимается только на замороженных (🔒/🔒🔒) экранах; событие снимка = событие заморозки.
> - Двухслойный детектор: layout-снимок (`getBoundingClientRect` → JSON, канон в git, блокирующий вердикт с порогом в px, дефолт 10px) плюс скриншот-хэш (локальный PNG + SHA-256 в MANIFEST в git, сигнальный).
> - Ноль новых зависимостей: devst генерирует Playwright-спеку в `tests/visual/` проекта и зовёт их же раннер (их baseURL, авторизация, fixtures, CI).
> - Каждый диф-отчёт несёт контекст заморозки: экран, статус и дата заморозки, версия макета figma-dump.
> **Связанное:** [ADR-011: UI freeze](../decisions/adr-011-ui-freeze.md) · [ADR-013: Default deny](../decisions/adr-013-default-deny.md) · [Feature 03: настольное окно devst UI](./03-devst-ui-desktop-window.md) · figma-dump

## 1. Суть и принципы

1. **Ловим именно верстку**: скриншот-диф, не функциональные тесты. figma-dump — эталон замысла («как должно быть»), baseline — страж факта («что заморожено»). Попиксельное сравнение с рендерами Figma — запрещено (шрифты/сглаживание).
2. **Заморожено = зафиксировано**: baseline снимается ТОЛЬКО на 🔒/🔒🔒 экранах; событие снимка = событие заморозки (запись в log, PR-видимость PNG).
3. **Адаптив — матрица**: каждый экран × набор вьюпортов (мобилка/планшет/десктоп); baseline и диф — на каждую ячейку матрицы.
4. **Ноль своих зависимостей**: devst НЕ тянет браузер — генерирует Playwright-спеку в `tests/visual/` проекта и зовёт их же раннер (их baseURL, авторизация, fixtures, CI). Канон — реестр; спека — производная («СГЕНЕРИРОВАНО devst»).
5. **Контекст заморозки в отчётах**: каждый диф подписан «экран Home, 🔒🔒 жёстко, заморожен 2026-09-08, макет dump: Home (v23)» — из ui-freeze.md.

## 2. Двухслойный детектор

Цель автора: **ловить блок, отъехавший на 20–100px, а не шрифт на пару пикселей** — это геометрия, а не пиксели. Поэтому детектор двухслойный:

| Слой | Что | Канон | Что ловит | Порог |
|---|---|---|---|---|
| **1. Layout-снимок (первичный)** | `getBoundingClientRect()` якорных элементов экрана → JSON | **в git** (КБ): точные числа, PR-диф текстом «top: 120 → 157» | сдвиги/размеры блоков, пропавшие элементы | в пикселях: дефолт 10px смещения/изменения, per-строка |
| **2. Скриншот-хэш (вторичный)** | PNG реального экрана | **локально** (`docs/baselines/images/`, gitignored) + SHA-256 в MANIFEST (git) | «выглядит иначе»: цвета, картинки, скругления | без допуска: любое несовпадение хэша = «посмотри глазами» |

- Layout-диф — **блокирующий** вердикт регрессии (числа в отчёте и PR); скрин-хэш — сигнальный (пиксельный диф считается локально со старой картинкой и прикладывается к отчёту).
- Субпиксельный/шрифтовый шум в геометрии не существует — порог честный в px.
- Якорные селекторы — негенерируемый `tests/visual/anchors.ts` проекта (по аналогии с profiles.ts); при разводке агент предлагает якоря по макету figma-dump.
- Командная эволюция: PNG→JPEG в git (×3–5 меньше) для ревью-видимости.

## 3. Дизайн (команды, реестр, отчёты)

### Реестр (расширение ui-freeze.md)

- Шапка: `Вьюпорты: 375x812, 768x1024, 1440x900` (дефолтный набор; per-строка может переопределить).
- Новые колонки строки: `URL` (роут экрана), опционально `Маски` (селекторы динамических зон: .feed, .timestamp) и `Допуск` (maxDiffPixels).

### Команды

- `freeze --baseline [--screen X]`:
  1. генерирует `tests/visual/freeze.visual.spec.ts` из реестра (только 🔒/🔒🔒 строки; заголовки тестов несут статус заморозки/версию макета);
  2. `playwright test visual --update-snapshots` (через раннер проекта);
  3. пишет канон: layout-JSON + `docs/baselines/MANIFEST.json` (коммит-хэш кода, дата, экраны×вьюпорты, SHA-256 скриншотов, статусы заморозки) + запись в log. PNG остаются локально (gitignored).
- `freeze --verify [--screen X]`:
  1. прогон спеки;
  2. консольная сводка + markdown-отчёт `docs/baselines/REPORT-<дата>.md`: экран / статус / вьюпорт / вердикт / ссылка на дифф;
  3. подсказка `playwright show-report` — их HTML-репорт с визуальным сравнением из коробки (глубокий разбор человеком);
  4. дифф на 🔒🔒 = жёсткая регрессия; на 🔒 = «уверен?»; незамороженные экраны не проверяются.

### Анти-фейк (верстка-специфика)

`animations: disabled`, ожидание `document.fonts.ready`, `deviceScaleFactor: 1`, маски динамических зон из колонки «Маски», стабильные fixtures данных (их e2e уже решают это), допуск per-строка.

### Клей с заморозкой

- Смена baseline (update-snapshots) без смены статуса — подозрительное событие: только с явного подтверждения автора (правило /ui-freeze) — «разморозка глазами», PNG-дифф виден в PR.
- SessionStart: если код замороженных файлов менялся позже baseline-коммита (git-даты — дёшево) → «N коммитов после baseline — прогони freeze --verify».
- pre-commit НЕ гоняет браузер (медленно); verify — ритуал по дрейфу/расписанию/CI (спека живёт в tests/ → CI проекта бесплатно подхватывает визуальные тесты).

## 4. Протокол решений

| № | Вопрос | Решение (2026-09-09) |
|---|---|---|
| 1 | Авторизация/стейджинг | **А**: колонка «Профиль» в реестре + негенерируемый `tests/visual/profiles.ts` проекта; agent-разведка при первом baseline. URL в реестре — путь, baseURL из playwright.config |
| 2 | Хранение картинок | **В+ хэш-канон** (платить нельзя, место беречь): канон в git = layout-JSON + MANIFEST с SHA-256; PNG — локально (gitignored). Диф MANIFEST в PR текстом. Потеря локальных PNG = осознанный пересъём (событие подтверждения). Командная эволюция: JPEG в git |
| 3 | Скриншот | **full-page по умолчанию**, per-строка «Селектор» опционально |
| 4 | Когда verify | **А** (SessionStart-подсказка дрейфа) + **CI-бесплатно** (спека в tests/visual — их GitHub Actions при пуше подхватит сам; pre-commit/браузер — нет; pre-push — отложено) |
| 5 | Порог/канон | **двухслойно** (см. §2): layout-JSON первичен (порог в px, дефолт 10), скрин-хэш вторичен; канон — локальная машина автора, пиннинг браузера lock-файлом |

## 5. Этапы

- [x] 1. Расширение реестра (колонки URL/Профиль/Селектор/Маски/Допуск/Вьюпорты) + парсер + защита от легенды-таблицы
- [x] 2. Генератор спеки (layout+скрин, анти-фейки) + `--baseline` (layout-JSON + MANIFEST с sha256 в git, PNG локально, gitignore-гигиена)
- [x] 3. `--verify`: layout-диф с порогом px (блокирующий, дефолт 10, per-строка «Допуск») + скрин-хэш (сигнальный, diffs/ для глаз) + REPORT-<дата>.md
- [x] 4. SessionStart-подсказка дрейфа: `baselineDrift` в check --json (коммиты, трогавшие замороженные пути, после кода baseline) → строка «N коммитов после baseline — freeze --verify» в первом же чате
- [ ] 5. Первый живой прогон на коммерческом фронте → ADR с итогами

Тесты (DoD): юнит+golden (visual-core, 10 кейсов), e2e с настоящим Chromium и дрейф-инъекцией (visual-e2e: baseline → +30px ловит числом/rc=1 → +3px ниже порога → только цвет: layout чист, хэш сигналит) — все зелёные (167 всего).

## 6. Режим pixelperfect — реализован (v1, 2026-09-09)

Реализовано: настройка `Изображения: git` в шапке реестра (плюс разовый флаг `--pixelperfect`). В режиме git: PNG коммитятся в репу (gitignore-запись для images/ убирается автоматически; обратное переключение возвращает её), `--verify` делает настоящий пиксельный диф (собственный PNG-декодер на node:zlib, ноль зависимостей): доля расхождения в % против допуска `Пиксель-допуск: N%` из шапки (дефолт 1%), допуск на антиалиасинг — ±10 на канал. Порог пройден на 🔒🔒 → блокирующая регрессия (rc=1); на 🔒 — предупреждение. Дефолт по-прежнему хэш-канон — тяжёлое попадает в репу только по явной настройке. CI-сравнимый рендеринг через пинненный образ браузера — Фаза 2.

## 7. Тестирование (обязательные автотесты — DoD фичи)

Без этих тестов фича не считается сделанной:

1. **Юнит (чистое ядро):** канонизация layout-снимка (rects → стабильный JSON: сортировка якорей, округление до 0.1px); layout-диф с порогом px (смещение 9px — чисто, 11px — событие; изменения размера; пропавший якорь); MANIFEST-хэши (совпал/не совпал/потеря изображения = событие пересъёма); генератор спеки — golden-file (реестр → ожидаемый текст спеки, вкл. заголовки со статусами заморозки).
2. **Интеграция (fake page):** фальшивый объект страницы с rect'ами и «скриншотами» — полный цикл baseline→verify без браузера, вкл. двухслойные вердикты.
3. **E2E (настоящий браузер, дрейф-инъекция):** devDep `@playwright/test` + мини-сайт фикстура (3 блока); сценарии: (а) чистый прогон — 0 событий; (б) CSS-сдвиг блока на 30px → layout-диф ловит С ЧИСЛОМ «~30px», вердикт — регрессия 🔒🔒; (в) правка только цвета → layout чист, скрин-хэш сигналит; (г) «шрифтовой шум» (эмуляция subpixel/AA) → ни один слой не срабатывает; (д) дрейф на 🔒 (мягко) → «уверен?», не блокирует. Отчёты сверяются на точные строки.

## 8. Не-цели

- Функциональные тесты, кросс-браузерная матрица (один браузер — их CI-дефолт).
- Сравнение с рендерами Figma (запрещено принципиально).
- Свой браузер/зависимости у devst.
