# Feature 02: Bug Hunt — pinpoint-репорты от тестеров-дизайнеров

> Русский · [English](../../features/02-bug-hunt.md)

> **Статус:** Реализовано для «Testing Staged» (S1–S4; остался S5 — живой прогон) · **Обновлено:** 2026-09-09
> **Суть:** два продукта на общей кодовой базе — **Testing Staged** (сниппет на стейджинге; закрывает 80% кейса «стили/картинка не так» при нулевой установке) и **Testing Extra** (Tauri, тяжёлый доступ: консоль/сеть/CDP для сложных багов). Разделяют формат репорта, конвейер ингеста и карточку для ИИ — обобщаются ровно там, где начинает работу разработчик с агентом. Тестер: пин на элемент + комментарий, или свободный комментарий без элемента; на выходе — машинно-обрабатываемые данные.
> **Ключевые факты:**
> - Ключевой инсайт: у devst уже есть словарь перевода — freeze-реестр (URL ↔ экран ↔ файлы), якорные селекторы, scan-ui, baseline, figma-dump — поэтому «вот тут криво» превращается в «починить эти файлы».
> - W3C Web Annotation JSON как формат репорта (CssSelector / TextQuote / Fragment) — интероперабельность по построению.
> - `devst bugs --ingest` превращает JSON-репорт в самодостаточную markdown-карточку: селектор + файлы + скриншот факта vs эталон макета.
> - Ограничение frontend-only: никакого бекенда — хранение в IndexedDB на стороне тестера, доставка одним самодостаточным JSON-файлом через любой мессенджер.
> - Сравнение вариантов слоя захвата (сниппет / букмарклет / MV3-расширение / Tauri); v1 — сниппет на стейджинге, Tauri — окно разбора, а не браузер тестера.
> **Связанное:** [Feature 01: Baseline-скриншоты](./01-baseline-screenshots.md) · [ADR-011: UI freeze](../decisions/adr-011-ui-freeze.md) · [Feature 03: настольное окно devst UI](./03-devst-ui-desktop-window.md) · figma-dump

## 1. Проблема

Тестеры-дизайнеры не знают имён компонентов и файлов. Сегодня их репорт = бумажка + скрин без контекста. Разработчик (или агент) тратит время на «найди где это». ИИ без pinpoint-инфы разбирается так же плохо.

## 2. Ключевой инсайт: у devst уже есть словарь перевода

| Что есть в devst | Что даёт для баг-репорта |
|---|---|
| UI-freeze реестр (URL ↔ экран ↔ файлы) | URL из репорта → экран → затронутые файлы |
| anchors.ts (экран → селекторы) | селектор из репорта → верификация/близость якорей |
| scan-ui (компоненты → файлы) | селектор → компонент → файлы |
| baseline (--verify) | свежий скриншот факта на нужном вьюпорте |
| figma-dump | эталон замысла того же экрана |

Тестер говорит «вот тут криво» на языке экранов; тулза переводит в язык файлов.

## 3. Конвейер

```
ТЕСТЕР (на сайте)                РАЗРАБОТЧИК                 АГЕНТ
─────────────────                ───────────                ─────
букмарклет → клик по элементу    docs/bugs/inbox/*.json      читает карточку:
→ форма (текст, серьёзность)  →  devst bugs --ingest    →   селектор+файлы+
→ JSON в буфер/скачан           (URL→экран→файлы;          скрин факт vs макет
                                 re-screenshot;             → чинит по pinpoint
                                 figma-рендер;
                                 карточка .md)
```

### Слой 1 — захват (букмарклет, ноль установки)

Букмарклет на любой странице: включает оверлей → тестер кликает элемент → подсветка + форма (текст, серьёзность: блокер/криво/ниит) → генерируется JSON:

```jsonc
{
  "@context": "http://www.w3.org/ns/anno.jsonld",  // W3C Web Annotation
  "body": { "text": "кнопка съехала", "severity": "криво" },
  "target": {
    "source": "https://site/orders?page=2",
    "selector": [
      { "type": "CssSelector", "value": ".order-list > li:nth(3) .btn-pay" },
      { "type": "TextQuoteSelector", "exact": "Оплатить" },   // якорь по тексту
      { "type": "FragmentSelector", "value": "xywh=pixel:512,340,88,36" }
    ]
  },
  "viewport": { "width": 375, "height": 812 },
  "userAgent": "...", "capturedAt": "2026-09-09T14:20:00Z"
}
```

Селектор строится жадно к стабильности: `[data-testid]` → `#id` → текстовая цитата + путь от ближайшего семантического предка. Скриншот не обязателен (см. слой 2) — но может прийти из `getDisplayMedia` или быть приложен вручную.

**Альтернатива слоя 1 (богаче):** `devst bugs --hunt` — открывает сайт в headed-Playwright с тем же оверлеем: качество селекторов движка Playwright, консоль и сетевые ошибки — автоматически в репорт. Минус: запуск нодой на машине тестера.

### Слой 2 — ингест (`devst bugs --ingest`)

1. Читает `docs/bugs/inbox/*.json` (или stdin/файл).
2. **Перевод**: URL → экран (реестр); селектор → компонент (scan-ui + anchors); экран → файлы (колонка «Файлы»).
3. **Скриншот-факт**: Playwright открывает `source` на `viewport`, ждёт селектор, снимает элемент + страницу целиком → `docs/bugs/evidence/<id>/`.
4. **Эталон макета**: рендер экрана из figma-dump (фрейм из колонки «Макет»).
5. Генерирует карточку `docs/bugs/BUG-<дата>-<n>.md`:

```markdown
# BUG-2026-09-09-01: кнопка съехала (криво)

> **Суть:** [тестер] «кнопка съехала» на /orders?page=2 @375x812
> **Перевод:** экран Orders → src/pages/Orders.vue, src/components/orders/**;
> элемент `.btn-pay` (текст «Оплатить»)
> **Доказательства:** факт (скрин элемента+страницы) | эталон (figma v23)
> **Статус:** новый

## Что видел тестер
(скриншот-факт, врезанный ссылкой на evidence/)

## Эталон
(figma-рендер)
```

6. inbox-файлы удаляются; карточки попадают в карту доки (`devst map`).

### Слой 3 — агент

Карточка — самодостаточный pinpoint: селектор + файлы + факт vs эталон. Агент читает, открывает файлы, чинит, закрывает статус (закрытие → строка в log сессии). Возможна авто-связка: элемент под 🔒🔒-заморозкой → карточка автоматически помечает «заморожено — координировать с автором».

## 4. Референсы (разведка, 2026-09-09)

| Инструмент | Что это | Берём |
|---|---|---|
| [Marker.io](https://marker.io/), [BugHerd](https://bugherd.com/) | коммерческий эталон жанра: пин на странице + CSS-селектор в репорте | UX-паттерн клик→пин→текст |
| [Crikket](https://github.com/redpangilinan/crikket) | open source, self-hosted, аналог Jam.dev: скрин+метаданные | формат метаданных, self-hosted подход |
| [BugPin](https://github.com/aranticlabs/bugpin) | open source: аннотации+скрины, GitHub-интеграция | общая идея — но у нас репорт уезжает в репу, что уже лучше |
| [Webvizio](https://webvizio.com/) | аннотации живых сайтов + Figma | мост «факт vs макет» — у нас figma-dump его закрывает |
| Jam.dev | коммерческий: полный тех-контекст (консоль, сеть) в один клик | чек-лист метаданных для --hunt |
| W3C Web Annotation | стандарт формата аннотаций (CssSelector, TextQuote, Fragment) | **формат JSON-репорта** — интероперабельность |
| rrweb / OpenReplay | запись сессий (тяжело) | НЕ берём: наш случай — точечные пины, не replay |

Ключевое отличие от всех: у них репорт уходит в Jira/трекер; у нас — **в репу как канон-маркдаун**, сразу в контур агента, с автопереводом в файлы.

## 4a. Юзер-флоу референсов (разведка, 2026-09-09)

Полный путь «чистый ПК тестера → репорт у ИИ» у каждого:

| Инструмент | Шаг 1: что качать/делать тестеру | Мобильное | Локальное/требования |
|---|---|---|---|
| **BugHerd** (эталон онбординга) | НИЧЕГО, если разработчик вшил JS-сниппет в сайт: тестер открывает ссылку — сайдбар уже там, пин → текст → готово. Без аккаунта (guest). Без сниппета — Chrome-расширение из Web Store (2 клика) | Работает на мобильных браузерах через сниппет (web-only, нативных приложений нет) | SaaS ~$42+/мес; свой сервер не нужен |
| **Marker.io** | Chrome-расширение из Web Store (клик «Add to Chrome») ИЛИ виджет-сниппет на сайте. Приглашение по email от разработчика | Через мобильный SDK (вшивается в приложение/сайт) | SaaS от $39/мес; caps по pageviews |
| **Jam.dev** | Только расширение (Chrome/Firefox/Edge), бесплатно для тестера. Одна кнопка → всё захвачено → шаринг ссылкой | Расширение desktop-only; мобильного нет (у них в roadmap) | SaaS; $12.4M инвестиций, 75k+ юзеров |
| **Crikket** (open source) | Свой инстанс (Docker) → расширение тестеру | нет данных | Self-hosted: Docker-сервер, Node+БД; сотни МБ, сервер должен жить |
| **BugPin** (open source) | Свой инстанс (Docker) → виджет | web | Self-hosted: Docker, аналогично |

**Ключевой паттерн рынка:** самый низкий порог входа — «JS-сниппет вшит в сайт» (BugHerd): тестеру не нужно НИЧЕГО качать, работает даже на телефоне. Расширение — fallback. Отдельный сервер (open source) — максимальный порог.

## 4b. Наш юзер-флоу (цель: порог ниже, чем у BugHerd, при нулевом сервере)

**Человек 1 — тестер-дизайнер (чистый ПК / телефон):**
- Вариант «сниппет на стейджинге» (рекомендуемый): разработчик добавляет ОДНУ строку `<script src="/bug-hunt.js">` на стейджинг (файл лежит в репе проекта, отдаётся дев-сервером; на проде его нет). Тестер: открыл ссылку → уже есть кнопка «баг» → клик по элементу → текст → «скачать репорт» → файл JSON ушёл разработчику через мессенджер. Ноль установки, работает на телефоне и планшете нативно.
- Вариант «букмарклет» (для чужих/продовых сайтов): перетащил кнопку в панель закладок один раз → кликнул на любом сайте → тот же оверлей.
- Требования к машине тестера: браузер. Всё. Ничего не качать, аккаунтов нет.

**Человек 2 — разработчик:**
- Получил JSON → положил в `docs/bugs/inbox/` → `devst bugs --ingest` (Node ≥ 18 + Playwright-Chromium ~280 МБ — уже есть для визуальной заморозки; скриншот-факт снимается здесь же) → карточка в docs/bugs/.

**Человек 3 — ИИ-агент:** читает карточку (селектор+файлы+факт vs макет) → чинит.

Общий вес локальной инфраструктуры: ноль серверов; на стороне дева — уже существующие devst+Playwright. bug-hunt.js весит единицы КБ и живёт в репе.

## 4c. Требования автора + сравнение сетапов захвата (2026-09-09)

**Требования:** почти ноль требований к окружению тестера (plug-and-play), вес НЕ «гигабайты», установка/использование brain-dead для тестера (программиста щадить желательно). Целевой сценарий — ПК; перспектива — Tauri-приложение или браузерное расширение. **Критичное:** состояние приложения В МОМЕНТ бага (ошибка исчезнет при перерисовке — захват только в момент клика, никакой пересъёмки при ингесте).

### Сравнение сетапов захвата

| Критерий | Сниппет на стейджинге | Букмарклет | Расширение (MV3) | Tauri-«браузер» |
|---|---|---|---|---|
| Установка тестером | **НИЧЕГО** (уже на странице) | перетащить в закладки (неочевидно) | ссылка → «Add to Chrome» (2 клика; нужна unlisted-публикация в сторе) | скачать exe (~15 МБ), вклеить URL |
| Мобильное | **да, нативно** | мучительно | нет (кроме FF Android) | нет |
| Любой сайт (прод/клиент) | только где вшит | да | **да** | да |
| Скриншот в момент | getDisplayMedia: 1 разрешение на сессию → точные кадры; html2canvas как запасной | то же, но CSP может резать | **captureVisibleTab — идеально, ноль трения** | CDP-скриншот — идеально |
| DOM в момент | **да, same-origin: outerHTML элемента (пароли маскируются)** | да, если CSP пустил | да (content script) | да (CDP) |
| Консоль/сеть | да (обёртки console/fetch/XHR с загрузки сниппета) | да | да | **да, нативно** |
| Свой браузер тестера | **да** (закладки, пароли, привычки) | да | да | **НЕТ — чужое окно** |
| Поддержка нами | JS-файл в репе (КБ) | JS-файл в репе | отдельный проект, стор | целый браузерный шелл |

### Решение (рекомендация, на утверждении)

- **v1 — сниппет на стейджинге**: закрывает главный сценарий (внутреннее тестирование стейджинга, ПК+мобильные), ноль установки, ноль своего софта. Скриншоты: при активации «режима багов» открывается getDisplayMedia-стрим (одно разрешение на сессию, выбор «этой вкладки») → каждый репорт = точный кадр момента; html2canvas — фолбэк. DOM-снимок элемента — обязательное поле.
- **v2 — расширение MV3** (unlisted в сторе, ссылка тестерам): любые сайты, включая прод/клиентские, captureVisibleTab без трения.
- **Tauri — НЕ браузер тестера, а окно РАЗБОРА для автора** (часть плана devst UI): просмотр карточек «факт vs макет», статусы. Аргумент против Tauri-захвата: тестер теряет свой браузер (пароли/закладки/привычки) — это трение каждой сессии, больше одноразовой установки расширения; CDP-плюс уже покрыт dev-режимом `--hunt`.
- Тяжёлый режим `--hunt` остаётся: программист воспроизводит по карточке, консоль/сеть — максимальной точности.

### Пейлоад репорта (по архетипам багов автора)

| Архетип | Что ловим |
|---|---|
| «сверстана не так / картинка полетела / не тот фон» | селектор + скрин момента + экран→figma-эталон при ингесте |
| «ошибка не на том языке» | **DOM-снимок (outerHTML) в момент** (текст ошибки байт-в-байт) + скрин |
| «неправильная валидация поля» | селектор поля + DOM (атрибуты/aria) + текст заметки |

Общее для всех: URL+роут, вьюпорт, таймстемп, заметка, серьёзность; скриншоты JPEG(q80, вьюпорт) в base64 внутри JSON — один файл, уходит через любой мессенджер.

## 4d. Два продукта (рамка автора, 2026-09-09)

Не версии одного инструмента, а два продукта на общей кодовой базе:

| | **Testing Staged** | **Testing Extra** |
|---|---|---|
| Кодовое имя | `staged` | `extra` |
| Что это | сниппет bug-hunt.js в репе проекта (одна строка на стейджинге) | Tauri-приложение (часть devst UI как режим) |
| Кейс | 80% багов фронта: «картинка не так, стили не те» | сложное: консоль, сеть, нерепродуцируемое |
| Тестер | свой браузер, ноль установки, ПК+мобильные | отдельное окно (осознанная цена за CDP) |
| Захват | DOM+селектор+скрин (getDisplayMedia-сессия) | CDP: идеальные скрины, консоль, сеть |

**Общее у обоих (точка обобщения):** формат репорта (W3C Web Annotation JSON, единая схема), `devst bugs --ingest` (перевод URL→экран→файлы, карточка), статусы карточек, поверхность агента. Продукты различаются ТОЛЬКО слоем захвата.

### MVP-поверхность тестера (минимальный набор, определён автором)

1. **Указать на элемент + комментарий** (пин).
2. **Свободный комментарий БЕЗ элемента** (о странице: «тут в целом фон странный», «форма регистрации вообще не открывается»).
3. Всё. Уровни серьёзности / кнопка скриншота — поверх, не блокеры MVP.

Свободный комментарий — это W3C-аннотация с target = URL и без селектора (модель поддерживает нативно); у карточки нет секции элемента, но есть факты экрана/страницы.

### Контракт машинной обработки (что получает ИИ)

Карточка BUG-NN несёт: заметку (дословно), время, URL+вьюпорт → экран реестра → файлы; при пине — селектор, текстовую цитату, DOM-снимок момента, скрин момента; при ингесте — figma-эталон экрана. Каждое поле либо машинно-обрабатываемо (селектор→файлы), либо готово к чтению агентом (DOM, скрин). Свободные комментарии группируются по экрану и попадают в ту же ленту.

## 4e. Хранение на стороне тестера и доставка (жёсткое ограничение: frontend-only, бекенда нет)

### Хранение: IndexedDB-сессия, не localStorage

localStorage (~5 МБ, строки) с картинками не справится. **IndexedDB**: сотни МБ, блобы нативно, переживает перезагрузки/переходы по страницам (один origin стейджинга = одна сессия). После релода оверлей восстанавливается: «у вас N неотправленных репортов» — ничего не теряется. Одна активная сессия на origin, с таймстемпом.

### Скриншоты: html2canvas по умолчанию, getDisplayMedia опционально

Ключевой инсайт: html2canvas рендерит **живой DOM в момент пина** — состояние ещё не ушло (ошибка на экране, форма заполнена), т.е. это честный «скрин момента», просто приближённый на экзотическом CSS. Зато:
- **ноль диалогов разрешений** (brain-dead требование!);
- **работает на мобильных** — включая iOS Safari, где getDisplayMedia отсутствует;
- same-origin стейджинг → без CORS-порчи картинок.

getDisplayMedia (идеальные пиксели) — opt-in тумблер «точные скрины» на десктопе (одно разрешение на сессию). Плюс всегда доступна ручная кнопка «прикрепить скрин» (file input → мобильная галерея: тестеры и так делают скрины кнопками).

### Доставка: один файл-пакет, руками, без сервера

1. В конце сессии тестер жмёт «Собрать репорты» → **один самодостаточный .json** (все репорты сессии, скрины внутри как base64 JPEG; 15 пинов ≈ 2–3 МБ).
2. Десктоп: скачивание. Мобильный: **Web Share API** (`navigator.share({files})`) — системный шаринг → Telegram/почта, к которым тестер привык. Фолбэк — скачивание.
3. Файл доходит до разработчика через любой мессенджер.
4. Дев: файл в `docs/bugs/inbox/` → `devst bugs --ingest` (распаковка base64 → `docs/bugs/evidence/`, карточки). После успешного ингеста — «очистить сессию» (тестер подтверждает).

Опционально (если у фронта когда-нибудь появится свой edge-endpoint, напр. serverless рядом с хостингом): флаг `window.__BUG_HUNT__.endpoint` — авто-POST. Не требование; базовый путь — файл.

## 4f. Дистрибуция: чистый TS внутри, обфускация для чужих реп (требование автора)

**Принцип:** источник и артефакт разделены. bug-hunt пишется на читаемом TS (`src/bug-hunt/` в репе devst, с дока-комментариями — наш инвариант качества). В целевую репу уезжает ТОЛЬКО собранный `bug-hunt.js`; режим сборки — флаг при выдаче:

```
devst bugs --emit [--readable] [--domain staging.example.com] [путь]
# дефолт — obfuscate; --readable — явный opt-in для своих реп
```

- **`--obfuscate` — ДЕФОЛТ** (решение автора, 2026-09-09): javascript-obfuscator на максимум — цель: получивший файл думает «не стоит того, пофиг» либо долго страдает. Профиль: control-flow flattening, string-array RC4 + перестановки, dead-code injection, переименование всего, числа-выражения, split-строки, self-defending (ломается при beautify).
- `--readable` (явный флаг для своих/пет-реп, где хотим дебажить): esbuild-бандл + terser-minify.
- `--domain` (рекомендуется всегда): **domainLock** — скрипт работает только на домене клиента: защита от выноса + привязка артефакта к конкретному клиенту.

**Честная модель угроз:** клиентский JS обратим всегда — цель не «невозможно», а «дорого»: с читаемого файла ИИ восстанавливает логику за минуты; с обфусцированного (flattening + RC4-строки) — часы ручной работы даже с помощью ИИ. Это отбивает охоту у команды клиента.

**Контракт корректности (этап S4):** один и тот же e2e-набор гоняется против ОБЕИХ сборок — обфускация не имеет права менять поведение (агрессивные опции иногда ломают; поэтому тест-дубль — обязательный гейт).

**Оговорки:** (1) объём ×3–5 и замедление — для стейджинг-оверлея приемлемо; (2) source-map в обфусцированной сборке — никогда; (3) если репа devst станет публичной, исходник bug-hunt либо остаётся в приватной части, либо принимаем, что защита — от клиента-получателя, а не от всего мира; (4) некоторые энтерпрайз-контракты ЗАПРЕЩАЮТ обфусцированные поставки — проверять договор клиента перед --obfuscate.

## 6b. Двусторонний оверлей (идея автора, 2026-09-09; долгосрочный TODO)

Bug Hunt — не только для тестеров. Оверлей — **общий мост «визуал ↔ код»**:

| Режим | Кто | Что делает | Куда пишет |
|---|---|---|---|
| 🐞 Баг | тестер | пин + комментарий | IndexedDB → пакет → `bugs ingest` → карточка |
| 🔒 Заморозка | разработчик | пин = «верстка готова к тесту» | **прямо в docs/ui-freeze.md** (без ИИ-посредника) |
| 👁 Вид | оба | кнопка «показать замороженное» | подсветка 🔒/🔒🔒/свободно на живой странице |

### Ключевая задача: визуал → компонент БЕЗ ИИ

Пин на q-btn → автоматически понять «это src/pages/OrdersPage.vue, компонент OrderList». Варианты:

1. **Build-time инструментация**: Vite-плагин devst добавляет каждому SFC-корню `data-devst-file="src/pages/OrdersPage.vue"` в dev/staging-сборках. Оверлей по клику читает атрибут → готовый маппинг. Ноль ИИ, ноль ручной работы.
2. **Протокол Vue DevTools**: `__VUE_DEVTOOLS_GLOBAL_HOOK__` — в dev-режиме оверлей может спросить дерево компонентов у Vue напрямую.
3. **Фолбэк — реестр**: как сегодня (URL → экран → файлы).

Вариант 1 — фаворит: дешёвый, явный, работает на стейджинге (не только в dev).

### Пин заморозки: что записывается

Клик по элементу в режиме 🔒 → прямой append в `docs/ui-freeze.md`:
- экран (из URL по реестру)
- файл (из data-devst-file или фолбэк)
- статус «жёстко» (дефолт для заморозок)
- дата = сегодня

**Без ИИ-посредника** (не карточка → потом реестр, а сразу в реестр) — быстрее, и разработчик видит результат в доках мгновенно.

### Режим 👁 «показать статусы»

Кнопка в оверлее → оверлей читает `docs/ui-freeze.md` (fetch с того же origin, если доки раздаются на стейджинге; или вшиты при emit) → подсвечивает элементы:
- 🔒🔒 жёстко — красная рамка + подпись
- 🔒 мягко — жёлтая
- свободно — без подсветки

Тестер и разработчик **видят на живой странице**, что уже заморожено.

### Зависимости

- Требует решения по компонент-маппингу (вариант 1 = Vite-плагин — отдельный артефакт, поставляется с devst)
- Режим 👁 безопасен (только чтение), может прийти раньше
- Режим 🔒 требует записи в доки (доступ к репе со стейджинга, или промежуточный буфер → `devst freeze --ingest-pins`)
