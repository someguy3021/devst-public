# Фича 11: Теги задач и уровни верификации — «одобрено сквозь пальцы» фиксируется

> Русский · [English](../../features/11-task-tags-and-verification.md)

> **Статус:** Реализовано (этапы 1–4) · **Обновлено:** 2026-10-10

**Суть:** задачи несут теги (закрытый словарь + свободные) и уровень верификации,
ставимый при закрытии — пять ступеней: deep / smoke / skim («сквозь пальцы») /
delegated / blind, плюс none, если не указан — каждая с датой и актёром
([фича 09](./09-actors-and-roles.md)). При close тулзы код-интеллекта
([фича 10](./10-code-intelligence-clean-room.md)) считают машинный срез по
объектам задачи (риск / blast / health) и вешают авто-теги; `devst audit` потом
показывает «одобрено не глядя — а вот что тулзы говорят сегодня».

**Ключевые факты:**

- честная мотивация — слова автора: «Я часто не проверяю твою работу, честно,
  или смотрю её плохо, или вообще не понимаю, что именно как ты сделал».
  Закрытие обязано различать «проверено тщательно» и «одобрено не глядя» —
  сегодня аудит-след у обоих одинаковый, и через месяц зоны риска доверия
  не найти;
- пять ступеней — решение автора (перевёрнуто с предложенных трёх): deep
  (тесты гонял, код читал) / smoke (тесты гонял, код не читал) / skim
  (результат глянул — «сквозь пальцы») / delegated (проверку делегировал —
  другой агент или человек проверил и доложил) / blind (не глядя, доверяю
  агенту); none — законный уровень, который audit подсвечивает;
- верификацию ставит только человек-актёр; агент может лишь предлагать
  теги-кандидаты; MCP-мутаций верификации нет;
- авто-теги от тулз при close: `risk-high` (риск ≥ 7/10), `blast-wide`
  (> 20 файлов), `health-findings` (≥ 1 находка).

**Связанное:** [фича 04](./04-task-registry.md) (реестр и close-гейт, на которых
это едет) · [фича 09](./09-actors-and-roles.md) (актёр-подписант) ·
[фича 10](./10-code-intelligence-clean-room.md) (срез при close и пересчёт
в audit) · [ADR-010](../decisions/adr-010-detect-dont-block.md) (детект,
не блокировка) · [ADR-017](../decisions/adr-017-hybrid-storage-md-sqlite.md)
(колонки реестра)

## Сценарии

1. Агент закончил работу → `task close` → CLI показывает срез («объекты:
   src/x.ts — риск 7/10, blast 14 файлов, health-находок 2») и спрашивает
   степень: `--verified deep|smoke|skim|delegated|blind` (не указана = none —
   честно).
2. Автор глянул результат мельком: `task close --verified skim` → задача несёт
   тег `skim` + дату + актёра; авто-теги добавлены (`risk-high` при риске ≥ 7).
3. Через месяц: `devst audit` → «задача (skim): сейчас риск 9/10, 5
   health-находок — одобрено сквозь пальцами 2026-10-09 → пересмотри».
4. Доска: `devst board` показывает теги; MCP `get_board` отдаёт их агенту —
   агент знает, где зона слабого доверия.
5. Напоминания: blind/skim-задачи со свежими находками тулз поднимают
   напоминание.

## Пять ступеней как шкала доверия

Для audit шкала читается так: лично проверено (deep/smoke) > глянул (skim) >
не глядя (blind/none); delegated — отдельная категория с пометкой «проверил
не сам». Уровень хранится с датой и актёром — «одобрено blind @author
2026-10-09» — запрашиваемый факт; подписанта даёт
[фича 09](./09-actors-and-roles.md). Агент не может ставить уровень ни себе,
ни чужой задаче — CLI-флаг `--verified` по определению человеческий жест
(команду запускает человек), MCP-мутаций этого поля нет.

## Теги: закрытый словарь + свободные

Предопределённые: `vibe` (написано агентом на доверии), `experimental`,
`hotfix`, `reviewed`, `debt` — плюс три авто-тега; свободные lowercase-теги —
для специфичного; линт предупреждает об одноразовых (использован ровно 1 раз).
Агентские теги ложатся только кандидатами, источник-актёр записывается.

## Ретроспектива: `devst audit`

Все skim/blind/none-задачи × что говорят тулзы сейчас: таблица «одобрено X
тогда, сейчас тулзы говорят Y», сортировка по деградации + remind-хук для
blind/skim-задач со свежими находками. Детект, никогда не блокировка
([ADR-010](../decisions/adr-010-detect-dont-block.md)): audit подсказывает,
решает человек — ничего не понижается автоматически.

## Не делаем

- Не блокировка закрытия без верификации: none — законный уровень, audit его
  подсвечивает.
- Не агентская верификация задач и не MCP-мутации verify.
- Не автопонижение уровней: ретроспектива подсказывает, решает человек.
- Не теги на ADR/доках — только задачи реестра (у документов — шапки).
