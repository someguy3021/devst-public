# Feature 05: система напоминаний: Reminder-провайдеры и devst remind

> Русский · [English](../../features/05-reminder-system.md)

> **Статус:** этапы 0–3 ГОТОВЫ (ADR-021, сессия 26) · **Обновлено:** 2026-09-12

**Суть:** все напоминания devst — один класс `Reminder` + реестр провайдеров
поверх существующих детекторов; один вход `devst remind [--json]`; один рендер
на носитель (SessionStart-панель, brief, UI-виджет «Сейчас»). Новое напоминание =
провайдер + строка в `collectReminders` — во все носители приезжает само.
Точка кастомизации — слайс «remind» в devst.json (пороги + off-список).

**Ключевые факты:**

- 8 провайдеров: conventions-errors, uncommitted, undocumented, baseline-drift, tasks-rotten, conventions-warnings, req-open, audit.
- Провайдеры — единственное место, где живёт семантика напоминаний; носители (хук/brief/UI) только рендерят.
- SessionStart-хук делает один CLI-вызов вместо нескольких рукописных блоков; блок brief и UI-виджет кормятся теми же провайдерами.
- Кастомизация: `"remind": { "auditDays": 14, "reqOpen": 1, "off": ["audit"] }` в devst.json; кривые поля молча откатываются к дефолтам.
- 3 решения протокола, 4 этапа — все готовы.

**Связанное:** [ADR-021](../decisions/adr-021-reminder-pipeline.md) · [ADR-010](../decisions/adr-010-detect-dont-block.md) (детект, не блокировка) · [фича 06](./06-kb-practice-installer.md) (потребитель: напоминания практик едут на этой системе) · задачи T-16 и T-13 (uncommitted — де-факто первый клиент этой системы)

## 1. Суть и потребители

| Потребитель | Как пользуется |
|---|---|
| Автор | настраивает пороги/выключатели в devst.json; видит один и тот же набор в панели, brief и окне |
| ИИ-агент | SessionStart приносит все напоминания одной пачкой (один CLI-вызов вместо трёх) |
| Будущие фичи | новый сигнал = один маленький чистый провайдер + тест; хук/UI не правятся |

## 2. Сценарии

1. Открытие сессии: хук зовёт `remind --json` один раз → генерический рендер
   (⚠ warn / ⏰ info, детали строками) в systemMessage.
2. `devst brief`: блок «Напоминания:» из тех же провайдеров (семантика одна,
   рендер свой).
3. Окно: вкладка «Сейчас» — виджет «напоминания (devst remind)» через
   KernelAdapter (Direct — сайдкар, Mock — фикстура).
4. Кастомизация: devst.json → `"remind": { "auditDays": 14, "reqOpen": 1, "off": ["audit"] }`.

## 3. Протокол решений

Все решения — 2026-09-12, решения автора по плану (в сессии захвачены дословно;
здесь переформулированы).

### 1. Полнота вместо скорости

Постоянное правило автора: выбирая между «сделать плохо, но быстрее» и «сделать
хорошо, но дольше» — всегда брать «хорошо, но дольше». Система делается целиком:
с группами-деталями (check-ошибки сохраняют поимённые списки: `Reminder.detail`),
с конфиг-слайсом и UI-виджетом в том же проходе, а не «потом».

### 2. «Отслеживать» = один источник семантики

Озабоченность автора: сигнал не должен раствориться в десяти идентичных
вариациях, размазанных по коду. Провайдеры — единственное место, где живёт
семантика напоминания; носители (хук/brief/UI) только рендерят. Подавление
(«видел — не показывай») и журнал срабатываний — вне (см. НЕ-цели).

### 3. Имя команды

`devst remind [--json]`.

## 5. НЕ-цели

- Подавление («видел — не показывай, пока состояние не изменится»): состояние +
  хранение — отдельная развилка (кандидат в парковку дальних идей).
- Журнал/метрики срабатываний: позже бесплатно вытекает из JSON-вывода, не сейчас.
- PostToolUse-гарды (freeze / линт-на-сохранение) — контекстные, файл-якорные;
  в эту систему не сливаются.
- Пуш-уведомления / фоновый демон — не наш формат (CLI, вызываемый по запросу).
